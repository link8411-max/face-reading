# 삼국지 일기토 1단계: 보이는 선택 (설계)

작성 2026-10-28. 기존 설계 `2026-10-28-samguk-duel-design.md` 위에 얹는 수정 설계다. 기존 설계와 어긋나는 곳은 이 문서가 이긴다.

## 1. 한 줄 요약

전투 규칙(맹>기>지>맹 상성, 능력치, 적 AI, 보스 예고)은 이미 있다. 플레이어에게 **하나도 안 보여서** 아무 버튼이나 누르는 게임이 됐다. 1단계는 "매 턴 무엇을 고를지 판단할 근거"를 화면에 드러내고, 의미 없는 선택지 하나를 치운다. 그림·틀·연출·밸런스는 손대지 않는다.

## 2. 왜

의뢰인 플레이 소감(2026-10-28): "전술도 상성이 뭔지도 모르면서 눌러서 싸우고, 동료도 없는데 +1 할 거냐고 물어보고, 능력치도 없다. 게임성이 없다."

포케로그가 재미있는 이유를 셋으로 줄이면 (1) 매 턴 머리를 쓴다 (2) 빌드가 내 것이 된다 (3) 전부 숫자로 보인다. 지금 게임은 규칙은 (1)(3)을 할 수 있게 짜여 있는데 화면이 숨기고 있다. 코드를 읽어 확인한 사실:

- 상성 `맹장 > 기장 > 지장 > 맹장`, 배수 1.4 / 0.75, 자속 1.2 (`battle.ts` `matchup`, `balance.ts`). 화면에는 "맹장 Lv3" 표찰과 메뉴 보조글 "맹·남은 3"뿐이라 **뭐가 뭘 이기는지 어디에도 안 적혀 있다.**
- 적 AI는 **내 선두 장수 유형을 보고 결정적으로** 가장 센 공격을 고른다 (`enemyAction`). 즉 적의 다음 행동은 미리 계산할 수 있는데 보스 필살기 예고 말고는 안 보여준다.
- 능력치(무력·지력·통솔·속도)는 피해 공식에 다 쓰이는데 화면 어디에도 없다. Task 8에서 "1배 폰에서 안 읽힌다"고 표찰을 뺐다.
- 보상 "동행 자리 +1"은 동행이 1명일 때도 나온다 (`rewards.ts` `slot.canUse`가 `partyMax < 4`만 본다).
- 명령은 한 번 누르면 고르기, 한 번 더 누르면 결정이다 (`DuelClient` `pending`). 고른 상태에서 대사창은 "▶ 일격 / 한 번 더 누르면 결정"만 띄운다. **이 자리가 미리보기를 보여줄 자리다.**

## 3. 목표 / 비목표 / 실패 조건

**목표**
1. 전투 중 어느 순간에도 플레이어가 "지금 상대는 뭘 하려 하고, 내 각 명령은 상대에게 유리한지 불리한지, 피해가 대략 얼마인지"를 화면에서 읽을 수 있다.
2. 상성 규칙을 외우지 않아도 된다. 규칙은 화면이 매번 알려준다.
3. 보상·영입 화면에서 고르는 대상의 능력치가 보인다.
4. 의미 없는 보상(동행이 꽉 차지 않았는데 자리 +1)이 안 나온다.
5. 1단계가 끝나면 의뢰인이 직접 한 판 돌려보고 2·3단계(교대 강화·특기·장비·길 선택·해금)를 할지 정한다.

**비목표**
- 새 기술·특기·장비·길 선택·영구 해금(2·3단계).
- 밸런스 수치 변경. `BALANCE`, 설계표, 적 AI의 실제 행동 분포는 그대로. `tests/duel/balance.*`가 지금 값으로 통과해야 한다.
- 새 그림·스프라이트·글꼴. 320×240 DOS 틀과 가로형/세로형 배치는 그대로.
- 튜토리얼 화면. 안내는 대사창 한 줄로 끝.

**실패 조건**
- 미리보기 숫자가 실제 피해와 다른 공식으로 계산된다(신뢰를 잃는다). 미리보기는 `damageRoll`과 같은 함수에서 나와야 한다.
- 적 의도 표시가 실제 행동과 어긋난다(예고와 다른 기술을 쓴다). 의도 계산과 실제 행동이 한 함수에서 나와야 한다.
- 가로형 1배(폰이 아닌 작은 창)에서 글자가 서로 겹치거나 상자를 넘친다.
- 기존 E2E `e2e/duel.spec.ts`와 vitest가 깨진다.

## 5. 규칙 쪽 변경 (`src/lib/duel/`)

### 5.1 적 의도 `enemyIntent` (battle.ts)

`enemyAction(state, rng)`를 둘로 나눈다.

- `enemyIntent(state): { skillId: string; sure: boolean }` — 난수 없음. 지금 `enemyAction`의 결정 부분(도발 중이면 기본 공격 / 예고 중이면 그 필살기 / 아니면 상성·자속 점수가 가장 높은 공격 기술, 보스는 필살기 제외)을 그대로 돌려준다. `sure`는 적 체력이 `LOW_HP`(30%) 이하이고 방어·회복 기술이 남아 있어 30% 확률로 딴 짓을 할 수 있으면 `false`, 아니면 `true`.
- `enemyAction(state, rng)` — `enemyIntent`를 부르고, `sure`가 `false`일 때만 지금과 같은 순서로 `rng()` 한 번을 뽑아 방어·회복으로 바꾼다. **난수를 뽑는 횟수와 순서가 지금과 똑같아야 한다**(시뮬레이터·밸런스 테스트 결과가 안 바뀐다).

교체 턴의 의미는 지금 그대로다: `resolveTurn`은 교체 전 상태로 적 행동을 정하므로, 화면에 보인 의도는 내가 교체해도 그대로 실행된다. 포켓몬의 교체와 같다. 이걸 문서와 미리보기 문구에 반영한다.

### 5.2 피해 미리보기 `damageRange` (battle.ts)

`damageRange(att, def, sk): { min: number; max: number }` — `damageRoll`과 같은 식에서 난수 계수를 0.85와 1.0으로 넣은 값. 치명타 없음. 일갈·방어 태세 상태도 지금 상태 그대로 반영한다. 위력 0이면 `{0,0}`. 구현은 `damageRoll`의 식을 복사하지 말고 공통 내부 함수로 빼서 둘이 같은 식을 쓰게 한다(실패 조건 1).

**미리보기가 반영하는 범위(제 판단)** — 선은 "이번 턴 내 행동이 실제로 어떤 기술로 나가는가"까지다.
- 선택 미리보기(6.3)는 고른 기술이 아니라 **실제로 나갈 기술**로 계산한다: 도발 중이면 기본 공격, 횟수가 0이면 기본 공격(`plannedSkill`·`usable`과 같은 규칙). 그때 둘째 줄에 이유를 적는다(`도발 중: 일격만`).
- 혼란(50% 실패)·속도 순서·먼저 쓰러뜨려 상대가 못 움직이는 경우·치명타는 반영하지 않는다. 미리보기는 "맞으면 이만큼"이다.
- 적 의도 줄(6.1)은 내 선택과 무관하게 "지금 상태 기준"이다. 내가 방어 태세를 고르면 선택 미리보기 둘째 줄에 `받을 피해 ~9`(절반)를 보여 주는 것으로 반영한다.
- 내 상태(도발·혼란·화상·일갈 들음)는 `FighterView.status: string[]`로 넘겨 선두 장수 유형·레벨 줄 옆에 짧게(`도발` `혼란` `화상`) 붙인다. 폭이 모자라면 한 개만.

### 5.3 상성 판정 문구 (battle.ts `resolveTurn`)

`TurnEvent`에 `eff?: 'win' | 'lose'`를 더한다. `hit` 사건에서 기술 유형 대 상대 유형이 이기는 상성이면 `eff:'win'`, 지는 상성이면 `'lose'`. 문구는 피해 문구 앞에 붙인다:

- win: `상성이 좋다! 관우에게 18의 피해!`
- lose: `상성이 나쁘다… 관우에게 7의 피해!`
- 그 외: 지금 그대로.

치명타 문구 `회심의 일격! `가 있으면 그 뒤에 온다(`회심의 일격! 상성이 좋다! …`). 기존 문구 테스트(`battleText.test.ts`)가 깨지면 그 테스트를 새 문구로 고친다.

### 5.4 기술 한 줄 설명 `SKILL_DESC` (skills.ts)

기술 id → 한 줄 설명(14자 이하, 보조글과 미리보기와 보상 카드가 같이 쓴다). 예:

| id | 설명 |
|---|---|
| strike/thrust/scheme | `기본 공격` |
| guard | `이번 턴 피해 절반` |
| shout | `상대 다음 피해 0.8배` |
| breathe | `체력 30% 회복` |
| fire | `피해 + 불 3턴` (주유 필살기는 1턴이므로 `burnTurns`로 계산) |
| confuse | `피해 + 혼란 1회` |
| ambush | `다음 피격 때 반격` |
| taunt | `상대 2턴 기본 공격만` |
| 필살기 | `큰 한 방` (+효과가 있으면 효과 설명) |

숫자는 `BALANCE`에서 읽어 만든다(`healRate` 등). 하드코딩 금지.

### 5.5 동행 자리 +1 조건 (rewards.ts)

`slot.canUse = (run) => run.partyMax < 4 && run.party.length >= run.partyMax`. 동행이 3명으로 꽉 찼을 때만 나온다. `run.test.ts`의 slot 관련 테스트를 조건에 맞게 고친다. 열전 문구는 그대로.

### 5.6 효과 없는 보상 대상 제외 (rewards.ts) — 제 판단

`attackStat`은 맹장·기장이 무력, 지장이 지력만 쓴다. 그래서 보검(공격 +8)을 지장에게, 병법서(지력 +10)를 맹장·기장에게 주면 숫자만 오르고 피해는 그대로다. 이것도 "+1 할래?"와 같은 가짜 선택이다.

- 보검·청룡언월도(`atk`)의 `targets`는 맹장·기장만, 병법서(`int`)는 지장만. 대상이 없으면 `usableReward`가 카드를 빼 준다.
- `Reward`에 표시용 구조화 필드를 더한다: `effect?: { stat: 'atk' | 'int' | 'speed'; amount: number }`. 6.5의 `무97→105` 표시는 이 필드로 만든다(`apply`를 돌려 보지 않는다).
- 숨 고르기 횟수·회복약 같은 다른 보상은 그대로.

### 5.7 밸런스 테스트가 흔들리면

5.5와 5.6은 보상 후보 풀을 바꾸므로 시뮬 분포가 미세하게 움직일 수 있다(봇은 slot을 자리 안 찼을 때 거의 안 집고, 병법서는 지장 없으면 2점이라 영향은 작을 것). 규칙: `BALANCE`와 `DIST_TARGETS`는 건드리지 않는다. `tests/duel/balance.*`가 깨지면 수치를 고치지 말고 어떤 지표가 얼마나 벗어났는지 보고한다. 그때 제가 (a) 허용 범위 조정 (b) 5.6 철회 중 고른다. 밸런스 테스트는 5.5·5.6을 넣은 직후 한 번 돌려 본다.

### 5.8 바꾸지 않는 것

`BALANCE`, 설계표, `nextEnemyId`, 항복 확률, 경험치, 보상 뽑기 확률(5.5·5.6의 대상 조건 말고는), 열전, 저장, 공유 키, 통계 전송.

## 6. 화면 쪽 변경

값은 전부 `view.ts`에서 계산해 `BattleView`에 담는다. `BattleScene`은 받은 글자를 자리에 놓기만 한다.

### 6.1 적 의도 줄 (항상 보임)

`BattleView.enemy.intent: { name: string; eff: 'win' | 'lose' | 'even'; dmg: { min; max } | null; sure: boolean; ult: boolean }`.

- `name`: 적이 다음에 쓸 기술 이름(5.1).
- `eff`: 그 기술 유형 대 **내 선두 장수** 유형의 상성(적 입장에서 win이면 나에게 불리).
- `dmg`: 내 선두 장수가 받을 예상 피해 범위(5.2). 위력 0이면 null.
- `sure`: false면 "흔들린다" 표시(방어·회복으로 바뀔 수 있음).
- `ult`: 예고된 필살기면 true(지금의 빨간 테두리 유지).

표시 자리(가로형): 적 초상 왼쪽, 이름(y=14)과 유형·레벨(y=56) 사이 y≈30~44. 보스 표찰 "보스"(y=30)가 있으니 보스일 때는 표찰 옆이나 아래. 글은 Galmuri9~11, 오른끝 맞춤 x=256. 내용은 한 줄: `다음 일격 ~18` 처럼 **기술 이름 + 예상 피해 최댓값**. `sure`가 false면 끝에 `?`. 필살기면 빨간색. 유불리는 색으로: 나에게 불리(적 win)면 빨강, 유리(적 lose)면 금색, 보통은 크림.

세로형도 같은 자리(위 170px는 가로형과 같다).

대사창의 처음 안내문(`제N전, 여포 등장! / 관우, 무엇을 할까?`)의 둘째 줄을 `여포: 일격 노림 (~18)`로 바꾼다. 가로형 14자 안에 안 들어가면 기술 이름만.

### 6.2 상성 표시

(a) 벌판 위 가운데, 두 장수 사이: 지금 `TURN n`(y=40) 아래 또는 옆에 한 단어. 내 선두 장수 유형 대 적 유형이 이기면 `유리`(금색), 지면 `불리`(빨강), 같으면 `비등`(크림). 이건 "내 기본 공격이 통하는가"의 요약이라 매 턴 한눈에 보인다.

(b) 메뉴 보조글: 지금 `맹·남은 3` → 공격 기술은 `유리·3회` / `불리·3회` / `보통·∞`(무제한은 `∞` 대신 글꼴에 있는 글자로, 없으면 `무제한`). 효과만 있는 기술은 `SKILL_DESC`의 앞 6자 정도(`피해 절반`, `30% 회복`, `반격`, `상대 묶기`). 이름과 겹치면 기존 규칙대로 보조글을 `3회`로 줄인다. 세로형 카드의 보조 줄은 폭이 넓으니 `유리 · 3회 · 큰 한 방`처럼 설명까지.

(c) 첫 판 안내: 웨이브 1 턴 1 대사창 셋째 줄(가로형 14자): `맹>기>지>맹 상성`. 같은 안내를 시작 화면 어딘가(출진 버튼 근처 빈 줄)에도 한 줄.

### 6.3 명령 미리보기 (고른 뒤, 결정 전)

`battle:prompt`가 지금 `{text, hint}`를 받는다. 이걸 `{lines: string[]}`로 바꾸거나 `preview` 필드를 더해 대사창 3줄을 전부 채운다. 가로형(14자) 기준:

- 공격 기술: `▶일격 맹 유리` / `예상 피해 12~14` / `한 번 더 → 결정`
- 효과 기술: `▶방어 태세` / `이번 턴 피해 절반` / `한 번 더 → 결정`
- 교체: `▶교체 조운(기)` / `적 일격에 불리` (교체 뒤 들어올 장수가 **이번 턴 적 의도**에 유리한지) / `한 번 더 → 결정`
- 기술이 바닥남(0회): `▶청룡언월도 참` / `힘이 남지 않았다` / 셋째 줄 비움, 결정 불가(지금 규칙 유지).

세로형은 Galmuri11로 줄이 넓으니 같은 내용을 덜 줄여 쓴다. 안내 숨김 설정(`HINT_KEY`, 몇 번 보고 나면 "한 번 더 누르면 결정"을 안 띄우는 기존 동작)은 셋째 줄에만 적용한다. 미리보기 1·2줄은 항상.

DOM 버튼의 `aria-label`에도 같은 요약(`일격: 유리, 예상 피해 12~14`)을 넣는다. 스크린리더용이자 E2E가 글을 확인할 길.

### 6.4 교체 줄

`교체 ▷ 조운(부상)` → `교체 ▷ 조운 유리` / `불리` / `비등`. 유불리는 **다음에 들어올 장수 유형 대 적 유형**. `(부상)` 표시는 유지하되 폭이 모자라면 유불리를 우선.

### 6.5 능력치 보이기

- **시작 화면**: 고른 장수 칸 아래(또는 행군 기록 창 첫 줄)에 `무력 97 지력 75 통솔 95 속도 55`. 세로형은 넉넉하니 한 줄, 가로형은 `무97 지75 통95 속55`.
- **보상 대상 고르기 창**(`pickView`): 줄 보조글 `Lv3 40/58` → 보상이 올리는 능력치만 `Lv3 40/58 무97→105`(5.6의 `effect` 필드로). 속도 보상은 `속55→63`. 능력치를 안 올리는 보상(회복약·부활약·기술 배우기)은 지금처럼 `Lv3 40/58`. 보여 주는 무력·지력은 보너스를 합친 값.
- **항복(영입) 창**: 영입 장수 이름 옆에 유형·레벨·`무력 92 지력 70 통솔 85`.
- **전투 화면**: 표찰은 다시 넣지 않는다(Task 8 결정 유지). 숫자는 6.1·6.3의 예상 피해로 체감시킨다.

보너스(보검 +8 등)는 `Fighter.bonus`에 있으니 합산값으로 보여준다(`무97+8`처럼 분리해도 된다, 빌더).

### 6.6 바뀌지 않는 연출

돌진·충돌·컷인·치명타 흔들림·보스 예고 빨간 테두리·카드 뒤집기 전부 그대로. 대사창 ▼ 깜빡임 그대로.

## 7. 저장·통계·열전 영향

없음. `SaveData` 그대로. `TurnEvent.eff`는 선택 필드라 옛 저장의 `lastEvents`도 읽힌다. GA·Supabase 전송 항목 변화 없음.

## 8. 테스트

- `battle.test.ts`: `enemyIntent`가 `enemyAction`과 같은 기술을 고른다(저체력 아닐 때 100%, 저체력일 때 `sure:false`); `damageRange`의 min/max가 난수 0.85/1.0의 `damageRoll`과 같다; `eff` 플래그와 문구.
- `balance.*.test.ts`: 수치 변경 없이 그대로 통과(리팩터가 분포를 안 바꿨다는 증거).
- `run.test.ts`: slot은 동행 3명일 때만 뽑힌다; 보검은 지장을, 병법서는 맹장·기장을 대상으로 내지 않는다.
- `view.test.ts`: `toBattleView`가 intent·eff·preview를 만든다, 14자 규칙, 교체 줄 유불리.
- `battleText.test.ts`: 상성 문구.
- E2E `duel.spec.ts`: 기존 통과 + 기술 버튼 `aria-label`에 `유리|불리|보통`이 들어 있다.

## 9. 빌더에게 맡기는 것

- 적 의도 줄과 상성 단어의 정확한 좌표·색. 320×240 안에서 안 겹치면 된다. 가로형 1배에서 Galmuri9가 읽히는지 스크린샷으로 확인.
- `battle:prompt` 이벤트의 모양(필드 추가냐 교체냐).
- `SKILL_DESC` 문구 다듬기(14자 규칙만 지키면 된다).
- 무제한 표기(`∞`가 글꼴 서브셋에 없으면 `무제한` 또는 생략).
- 시작 화면 능력치 줄의 위치.

## 10. 범위 밖 (2·3단계, 1단계 플레이 후 결정)

- 2단계: 교대 출전 강화(교체 턴 보정), 장수별 특기 1회, 장비 두 칸(무기·말).
- 3단계: 웨이브 사이 길 선택(약한 적/강한 적/주막/상인), 보스 격파 시 시작 장수 해금, 사건 글.
- 기력 자원, 영입 교환 선택, 카드덱 전투(검토했다가 보류).
