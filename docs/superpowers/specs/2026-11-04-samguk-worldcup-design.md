# 삼국지 장수 월드컵 설계

2026-11-04. 사용자와 대화로 정한 내용. "내 판단"은 사용자가 따로 정하지 않아 설계자가 정한 부분이다.

## 왜 만드나

- 인물열전의 응원 버튼은 "누르고 끝"이라 너무 수동적이다(사용자). 들어온 사람이 직접 고르고, 겨루고, 자랑하게 해야 다시 오고 공유한다.
- 이상형 월드컵은 한국에서 이미 익숙한 놀이라 설명 없이 바로 한다. 결과 카드는 공유하기 좋다.
- 단, **얼굴만 보고 고르는 월드컵이면 안 된다.** 재미난 읽을거리를 주고 고르게 해야 한다(사용자).
- 모든 선택이 모여 주제별 우승 순위가 생긴다. 응원 버튼보다 훨씬 많은 참여 데이터가 쌓인다.
- 순서: 인물열전을 먼저 배포하고 그다음 만든다(내 판단, 사용자가 반대하지 않음). 열전 127편은 검색 색인이 빠를수록 이득.

## 목표

1. 주제별 16강 월드컵 4종: 최강 무장, 최고 책사, 삼국지 여인, 전체 무작위.
2. 대결마다 두 장수의 읽을거리(눈길 끄는 한 줄 + 알고 보면 한 가지) — 사용자가 시안을 보고 "그 정도면 된다"고 확인한 분량.
3. 두 장수가 실제로 얽힌 사이면 "이 둘이 만난 장면" 한 줄.
4. 고르면 실제 선택 비율과 다음 대결.
5. 끝나면 우승 카드("나의 최애 장수"), 결승까지의 길, 공유, 그 장수의 열전 링크, 다른 판 하기.
6. 주제별 우승 순위(실제 집계).

## 목표가 아닌 것

- 로그인, 닉네임, 개인 기록 보관.
- 32강·64강, 직접 대진 만들기(내 판단: 16강이면 15번 고르고 끝나 1~2분, 부담이 없다).
- 초상화 없는 인물 출전(그림 없는 대결은 재미가 없다).
- 새 글 작성. 읽을거리는 이미 사실 검토·인용 점검을 마친 열전 데이터만 쓴다.

## 하면 안 되는 것 (실패로 본다)

- 가짜 숫자. 비율·순위는 실제 집계만. 아직 아무도 안 고른 대결은 "이 대결을 처음 골랐어요".
- 기록에 없는 문장. 카드 문구와 "만난 장면"은 열전 데이터에 이미 있는 것만 쓴다.
- 연의와 정사를 섞어 보이게 하는 것. 읽을거리 문장은 열전에 붙은 연의/정사 표시를 그대로 따른다.
- 투표 부풀리기에 다시 구멍을 내는 것(열전 투표와 같은 서명 쿠키·첫날 IP 기준을 쓴다).

## 판 구성

| 판 | 출전 16명 |
|---|---|
| 최강 무장 | 초상화 있는 인물 중 닮은꼴 데이터 `stats.무력` 상위 16명(동점은 `stats.통솔`) |
| 최고 책사 | `stats.지력` 상위 16명(동점은 `stats.정치`). 책사가 아닌 화타(의원)는 뺀다(내 판단). 2026-11-04 기준 제갈량·사마의·방통·곽가·가후·주유·순욱·육손·순유·법정·진궁·종회·황월영·조조·정욱·이유 |
| 삼국지 여인 | `gender: '여'`이고 초상화 있는 인물. 지금 15명이라 판마다 15명 중 무작위 8명으로 8강(내 판단). 초상화가 늘어 16명 이상이 되면 판마다 무작위 16명으로 16강. 판 구성 함수가 인원 수로 자동 결정 |
| 전체 무작위 | 초상화 있는 인물 전원 중 매번 16명 무작위 |

- 능력치 숫자는 우리가 정한 게임 값이라 화면에 "역사적 강함"처럼 쓰지 않는다. 판 이름은 "최강 무장"이지만 순위 기준을 설명할 때는 "코에이 스타일 무력 기준"이라고 밝힌다(내 판단).
- 대진은 매번 섞는다(같은 판도 할 때마다 다른 대결).
- 판끼리 출전자가 겹쳐도 된다(황월영은 책사·여인 둘 다, 조조는 책사). 2026-11-04 기준 최강 무장 16명: 여포·장비·관우·마초·전위·조운·허저·방덕·감녕·태사자·손책·장료·안량·황충·문추·손견.
- 고정 판(무장·책사·여인)은 출전자가 정해져 있어 판별 우승 순위가 의미 있다. 무작위 판은 우승 순위 대신 "많이 이긴 장수" 순위에만 반영(내 판단).

## 한 대결 화면 (시안 확인함)

- 위: 판 이름 · 진행(예: `최강 무장 16강 · 3/8`).
- 질문 `둘 중 누가 더 끌리나요?`
- 두 카드 나란히(모바일 2열): 초상화, 이름, `summary` 첫 문장(눈길 끄는 한 줄), `알고 보면:` + `funFacts` 중 하나(대결마다 무작위 하나, 내 판단).
- 두 사람이 열전 관계 데이터로 이어져 있으면 카드 아래 `이 둘이 만난 장면:` + 그 관계 `note`(출처 표시 그대로). 없으면 이 줄 없음.
- 카드를 누르면 고른 쪽 강조 → 비율 안내 → `다음 대결` 버튼. 비율 규칙(내 판단, 열전 대결 투표의 '10명 미만이면 비율 숨김'과 같은 기준):
  - 비율은 **내 표를 뺀 다른 사람들** 기준이다(서버가 저장 전 집계를 읽거나 내 표를 빼서 돌려준다). 그래서 첫 사람이 "100%"를 보지 않는다.
  - 다른 사람 0명: `이 대결을 처음 골랐어요`
  - 1~9명: `지금까지 N명이 이 대결을 골랐어요`(비율 없음)
  - 10명 이상: `다른 사람들은 N%가 ○○를 골랐어요`
  - 비율은 **판과 상관없이 그 두 사람 대결 전체** 기준(무작위 판에서도 같은 둘이 만나면 같은 집계, 내 판단 — 판별로 나누면 거의 늘 "처음"이 된다).
- 저장이 실패하거나(429·503·네트워크) 늦어도 놀이는 멈추지 않는다. `다음 대결` 버튼은 바로 누를 수 있고, 비율 칸은 응답이 오면 채우고 실패하면 `지금은 다른 사람 선택을 불러오지 못했어요`(내 판단).
- 조사(을/를, 이/가)는 받침에 맞춘다.

## 끝 화면

- `나의 최애 장수` 카드: 큰 초상화, 이름, 첫 문장, 판 이름.
- 결승까지의 길: 이긴 상대 4명(16강→결승) 이름 줄.
- 버튼: `공유하기`(기존 공유 흐름, 공유 링크 `/samguk/cup/r/<판>/<우승 id>`, 미리보기 카드 "나의 최애 장수는 관우. 너는?"), `<이름> 열전 보기`, `다른 판 하기`.
- 판별 우승 순위 상위 5명(실제 집계, 아직 없으면 생략) + `전체 순위 보기`.

## 페이지

- `/samguk/cup`: 판 고르기(시안의 네 카드). 판마다 실제 플레이 수가 있으면 `지금까지 N판` 표시.
- `/samguk/cup/[판]`: 진행 화면(클라이언트). 판 키: `warrior`, `strategist`, `women`, `random`.
- `/samguk/cup/ranking`: 판별 우승 순위 + 많이 이긴 장수(ISR, 열전 순위와 같은 주기).
- `/samguk/cup/r/[판]/[id]`: 공유 착지(noindex, 1인칭 미리보기, "나도 해보기").
- 검색: `/samguk/cup`과 순위만 사이트맵. 제목 예: `삼국지 장수 월드컵 | 최강 무장·책사·여인 16강 – 운명을 읽다`(48자 규칙 따름).
- 연결: 열전 허브 바로가기, 열전 페이지 대결 투표 근처 `이 장수로 월드컵 하기`(그 장수가 출전하는 판), 닮은꼴 결과의 `NextTests` 옆이나 아래(내 판단), 메뉴 얼굴 탭에 항목.

## 저장

- 기존 `people_votes` 테이블과 서명 쿠키·첫날 IP 해시를 그대로 쓴다(내 판단 — 새 테이블 없이).
  - 대결 하나: kind `cup_match`, target `<pairKey(a,b)>`(판 없이, 위 비율 규칙), option = 고른 id. 요청에는 판 키도 보내고 서버는 두 사람이 그 판 후보(판 구성 함수의 전체 후보 명단)에 있는지만 확인한다.
  - 우승: kind `cup_win`, target `<판>`, option = 우승 id.
  - 같은 날 같은 대결을 다시 하면 선택을 바꾸는 것으로 처리(기존 merge 규칙). 우승도 판마다 하루 1건(마지막 결과로 바뀜).
- `people_votes`의 `kind` check 제약에 `cup_match`, `cup_win` 추가하는 SQL을 `docs/people-votes.sql`에 덧붙인다(아직 실행 전이라 원래 CREATE에 넣어도 됨).
- 집계: 대결 비율은 그 pair 행만, 우승 순위는 판별 `cup_win` 집계, 많이 이긴 장수는 `cup_match`에서 option별 합.
- 요청 제한(내 판단): 한 판이 약 16번 요청이고 통신사 IP를 여럿이 함께 쓰므로 월드컵 요청은 열전 투표와 따로 센다. 월드컵은 IP당 10분 200번, 열전 투표는 지금처럼 60번.
- 진행 상태(지금 몇 강, 이긴 사람들)는 브라우저 메모리. 새로고침하면 처음부터(내 판단, 짧은 놀이라 저장 안 함).
