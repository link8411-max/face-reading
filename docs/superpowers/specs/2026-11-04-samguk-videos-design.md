# 삼국지 쇼츠 ↔ 사이트 연결 설계 (2026-11-04)

## 왜

유튜브 채널 "삼국지 한 장면"(@unse_ai, `UCQvI9qIC3pIq_24_x5XE_3g`)에 올린 쇼츠 3편이 첫날 300~1,000회를 기록했다(하후돈 1,008·적벽 354·도원결의 305, 11/4 API 기준). 반면 유튜브 → 사이트 유입은 14일 동안 2명이었다. 쇼츠의 설명·댓글 링크는 눌리지 않고, 링크 스티커는 브랜드 협찬 전용이라서 쓸 수 없다. 그러니 지금 할 수 있는 연결은 두 가지다.

1. **사이트 → 영상**: 사이트를 찾은 사람이 열전·결과 화면에서 바로 쇼츠를 본다. 사이트에 더 오래 머물게 하고, 유튜브 조회수(퍼가기 재생도 집계됨)와 구독을 늘린다.
2. **영상 → 사이트**: 채널 프로필 링크가 이 사이트의 영상 페이지로 오게 한다. 쇼츠 설명에 이미 "나는 누구를 닮았을까? → 채널 프로필 링크"라고 쓰여 있으니, 그 링크를 받을 페이지가 필요하다. 덧붙여 영상 구조화 데이터를 넣어 구글 동영상 검색에서 우리 주소가 걸리게 한다.

## 목표

- 쇼츠를 올리기만 하면 사이트에 자동으로 나타나고, 해시태그에 적힌 인물의 열전에 붙는다. 코드 수정 없이.
- 열전·결과 화면 안에서 바로 재생된다. 유튜브로 나가지 않는다.
- `/samguk/videos`가 채널 프로필 링크의 착지 페이지 역할을 한다. 영상에서 닮은꼴 테스트와 열전으로 이어지게 한다.
- 재생·구독 클릭·영상 페이지에서 시작한 테스트를 GA로 센다. 2주 뒤 판단할 수 있게.

## 하지 않는 것

- 영상 업로드·제목 관리(유튜브 스튜디오에서 한다).
- 댓글·좋아요 수 노출, 유튜브 로그인 연동.
- 롱폼 모음 영상 제작(효과를 본 뒤에 결정한다).

## 실패로 보는 경우

- 영상 칸 때문에 열전·결과 화면이 무거워지는 경우. 첫 화면에서 iframe을 불러오면 실패다.
- API 키가 브라우저 코드나 저장소에 노출되는 경우.
- API 장애가 나서 페이지가 깨지거나 빌드가 실패하는 경우.
- 엉뚱한 인물에 영상이 붙는 경우(예: `#장비`가 아닌 영상이 장비 열전에 붙음).

## 데이터

**출처**: YouTube Data API v3. 키는 Vercel 환경변수 `YOUTUBE_API_KEY`(Production, 11/4 등록). 구글 클라우드 프로젝트 `unse-ai-513714`의 키이고 YouTube Data API로 제한돼 있다. 로컬·미리보기에는 키가 없으므로 아래 RSS 대체 경로가 동작해야 한다.

- 업로드 재생목록 `UUQvI9qIC3pIq_24_x5XE_3g` → `playlistItems.list`(50개씩 페이지) → `videos.list(part=snippet,statistics,contentDetails)`.
- 호출당 1단위다. 1시간마다 갱신하면 하루 100단위 미만이고, 할당량은 10,000이다.
- **대체 경로**: 키가 없거나 API가 실패하면 `https://www.youtube.com/feeds/videos.xml?channel_id=…`(키 불필요, 최근 15편, 조회수 포함)를 쓴다. 이것도 실패하면 빈 목록을 반환하고, 영상 칸은 숨긴다.
- 서버 전용 모듈(`src/lib/videos/`)에서 `fetch(..., { next: { revalidate: 3600 } })`로 부른다. 열전은 정적 생성(`generateStaticParams`, `dynamicParams=false`)이라 페이지 단위 ISR 1시간이 된다. 빌드 중 API가 실패해도 빌드를 깨면 안 된다.

**영상 한 건의 형태**: `{ id, title(해시태그 제거), publishedAt, durationSec, views, thumbnail, people: string[], isShort }`
- `isShort`: 재생 시간 3분 이하. 롱폼은 이번 범위에서 목록에만 넣고 열전에는 붙이지 않는다.
- `people`: 설명·제목의 해시태그(`#유비`)를 `allSamgukCharacters`의 `name`과 **정확히 일치**할 때만 인물 id로 바꾼다. 결과 순서는 해시태그 순서를 따른다.
- **수동 보정 파일** `src/content/videoOverrides.ts`: `{ [videoId]: { people?: string[], hide?: boolean, event?: string } }`. 해시태그가 틀렸거나, 숨기거나, 사건 묶음을 지정할 때 쓴다. 보정 값이 해시태그보다 우선한다.
- 사건 묶음(필터용): 우선 보정 파일의 `event`(예: `도원결의`, `적벽`)만 쓴다. 재생목록 연동은 하지 않는다.

**현재 3편의 기대 매핑**(테스트 기준값, 11/4 실제 설명 해시태그 기준):
- `2U3ZFgCdnzU` 도원결의 → 유비·관우·장비
- `R-lrShfZU7s` 하후돈 → 하후돈·조조 (`#하후돈 #조조`. 조조 열전에 붙는 것도 맞다고 본다. 내 판단)
- `NejqojdriBg` 적벽대전 → 제갈량·조조·주유

**한 열전에 영상이 여럿일 때 순서**: 그 인물이 첫 해시태그 인물인 영상(주인공)을 앞에 두고, 그다음은 최신순이다. 예를 들어 조조 열전에서는 조조가 주인공인 영상이 생기면 맨 앞에 온다.

**RSS 대체 경로의 한계**: 재생 시간이 없다. 이 채널은 쇼츠 전용이므로 RSS로 받은 영상은 `isShort=true`로 보고, `VideoObject`에서는 `duration`을 뺀다.

**롱폼**: 이번 범위에서는 열전·피드·허브 띠·격자 어디에도 내지 않는다(현재 0편). 롱폼이 생기면 그때 가로 카드를 설계한다.

  - 테두리 색: 라이벌은 `blush`, 원수는 `accent`, 나머지는 `line`이다. 색만으로 구분하지 않도록 묶음 머리 글자가 늘 붙어 있다.

**① 열전 `/samguk/people/[id]`**
- 위치: "알고 보면 재밌는 이야기" 다음, 쿠팡 배너 앞. 제목은 "{이름} 이야기, 1분 영상".
- 1편이면 세로 카드 하나(폭 최대 280px, 가운데)다. 2편 이상이면 가로 스크롤 카드다.
- 아래 줄에 "유튜브에서 구독"과 "영상 더 보기 → /samguk/videos"를 둔다.
- **관계 인물 영상 (사용자 요청)**: 열전에는 이미 관계도와 관계 목록(`relationsOf(id)`)이 있다. 이 관계를 따라 영상도 이어지게 한다.
  - 칸은 두 줄이다. 첫 줄은 "{이름}이 나오는 영상"(해시태그에 이 인물이 있는 영상)이다. 둘째 줄은 "관계 인물 영상"으로, `relationsOf(id)`에 있는 인물(`otherId`가 있고 열전이 있는 인물)이 나오는 영상 중 첫 줄과 겹치지 않는 것이다.
  - 둘째 줄 카드에는 관계 말을 붙인다. 예: 하후연 열전 → "사촌 형제 · 하후돈" (말은 `RelationView.label` 그대로 쓴다).
  - 모든 영상 카드에는 **등장 인물 칩**을 단다. 칩을 누르면 그 인물의 열전으로 간다. 지금 보고 있는 인물은 칩에서 뺀다.
  - 순서: 첫 줄은 주인공 우선, 그다음 최신순이다. 둘째 줄은 관계 목록 순서(내 relations 먼저)를 따르고, 둘째 줄은 최대 6편이다.
  - 둘째 줄 카드는 세로 썸네일 150×266이다. 썸네일 왼쪽 아래에 관계 인물 얼굴 + "관계 말 · 이름" 띠를 얹고, 아래에 제목과 조회수를 둔다. 줄은 가로로 넘긴다.
- 첫 줄 영상 카드(시안 ①): 폭 가득, 9:16(최대 높이 560px). 왼쪽 위에 "조회수 N회 · 길이" 띠, 가운데에 재생 버튼을 둔다. 그 아래에 제목, "함께 나오는 인물" 얼굴 칩(→ 열전), 버튼 두 개(유튜브에서 구독 / 영상 더 보기)가 온다. 첫 줄이 2편 이상이면 같은 크기 카드를 가로로 넘긴다.
- 열전 칸 순서: 요약·재밌는 이야기 → **영상 칸(첫 줄)** → **상관도(⓪)** → **관계 인물 영상(둘째 줄)** → 쿠팡 배너 → 닮은꼴 배너 → 이하 지금 그대로.
- 첫 줄과 둘째 줄이 모두 비면 이 칸 자체를 렌더링하지 않는다.
- 영상이 있으면 `VideoObject` JSON-LD를 넣는다(name, description, thumbnailUrl, uploadDate, duration, embedUrl, contentUrl=쇼츠 주소, interactionStatistic).

**② 삼국지 닮은꼴 결과 `/samguk`(결과 상태)과 공유 착지 `/samguk/r/[key]`**
- 결과 인물에게 영상이 있으면 공유 버튼·쿠팡 배너 아래에 "내 장수 이야기, 1분 영상" 카드를 넣는다(시안 ④). 왼쪽은 세로 썸네일 112×199(재생 버튼), 오른쪽은 제목·조회수·"영상 보기" 버튼이다. 누르면 그 자리에서 재생하지 않고 `/samguk/videos?v=<id>` 피드를 연다. 결과 화면은 캡처 대상이므로 이 카드에는 `no-screenshot`을 붙이고, iframe은 두지 않는다.
- 그 아래에 **"내 장수와 엮인 장수들"** 초상화 5칸(52px)을 둔다. `relationsOf` 앞에서부터 초상화와 열전이 있는 인물 5명이고, 칸마다 이름과 관계 말을 달고 누르면 열전으로 간다. 오른쪽 위 "상관도 전체"는 결과 인물 열전으로 간다. 영상 유무와 관계없이 관계가 있으면 그린다. 이것도 `no-screenshot`이다.
- 결과 화면은 클라이언트 컴포넌트이므로, 영상 목록을 서버에서 받아 props로 넘기거나 `/api/videos` 같은 캐시된 라우트에서 받는다. 어느 쪽이든 키는 서버에만 둔다. (빌더 판단)

**③ 영상 페이지 `/samguk/videos`** (채널 프로필 링크의 착지)
- 기본 화면은 세로 썸네일 2열 격자(최신순)다(시안 ②). 맨 위에 제목 "쇼츠로 보는 삼국지"와 한 줄 소개를 두고, 그 아래에 남색 띠 "내 얼굴은 어떤 장수?"(초상화 3장 겹침 → /samguk)를 둔다.
- 격자 카드: 9:16 썸네일 + 왼쪽 아래 등장 인물 얼굴 겹침 + (24시간 안이면) 왼쪽 위 NEW 배지. 아래에 제목(해시태그 뺀 것)과 "조회수 N회 · 인물 이름들"을 둔다.
- 인물 필터는 초상화가 달린 칩이다("전체 N", "조조 2"처럼 편 수가 2 이상이면 숫자를 붙인다). 영상이 있는 인물만 나오고 가로로 넘긴다. 사건 필터는 `event`가 있을 때만 둔다.
- 영상 수가 홀수면 마지막 빈칸은 비워 둔다. 시안의 "다음 편 준비 중" 칸은 넣지 않는다(예고 데이터가 없으므로).
- 썸네일을 누르면 **전체 화면 세로 피드**가 열린다. 누른 영상부터 시작하고, 위아래로 넘긴다(CSS scroll-snap). 화면에 보이는 영상만 iframe이고 나머지는 썸네일이다.
- 피드 화면(시안 ③): 위쪽에 닫기(×, 44px)와 "i / N · 위아래로 넘겨요"를 둔다. 오른쪽 가장자리에는 위치 막대를 둔다. 아래쪽은 어둡게 깔고 그 위에 제목, 조회수, 등장 인물 얼굴 칩("{이름} 열전" → 열전), 버튼 "나는 누구 닮았을까?"(→ /samguk)와 "구독"을 얹는다. 닫으면 격자로 돌아간다.
- 겉에 얹은 글·버튼이 유튜브 플레이어 조작부(아래쪽)와 겹치지 않게, 플레이어는 겉 글 영역 위까지만 차지한다. 정확한 배치는 빌더 몫이다.
- 이렇게 정한 이유(내 판단): 격자는 한눈에 고르기 좋고 검색 엔진이 읽기 쉽다. 피드는 쇼츠에서 온 사람에게 익숙하다. 두 가지를 다 얻는다.
- `?v=<id>`로 들어오면 그 영상으로 피드를 바로 연다. 공유용이고, 채널 프로필 링크에는 쓰지 않는다. canonical은 언제나 `/samguk/videos`이고 색인 대상도 이 기본 주소 하나다.
- `ItemList` + 각 `VideoObject` JSON-LD를 넣는다. 사이트맵에 `/samguk/videos`를 추가한다.
- 저장소 규칙상 일반 내용 페이지로 다룬다. 그래서 `layout.tsx` 메타데이터, `pageGuides.ts` 본문 + `<PageGuide>`, 사이트맵 `LAST_MODIFIED` 갱신을 모두 한다. 쿠팡 다이나믹 배너(subId `videos-hub`)는 격자 아래에 두고, 전체 화면 피드 안에는 두지 않는다. 하단 탭은 새로 만들지 않는다(`tabForPath`에서 얼굴 탭 소속, 기존 `/samguk` 하위와 같음).

**④ 허브 띠**
- `/samguk/people`(열전 허브)와 `/samguk`(시작 화면, 결과 전)에 "쇼츠로 보는 삼국지" 가로 띠로 최신 4편을 보여 준다. 누르면 `/samguk/videos?v=<id>`로 간다.

## 측정 (GA)

`src/lib/analytics.ts`에 이벤트를 추가한다.
- `video_play` `{ slot, result_id }`: slot은 `people`·`result`·`videos`·`hub`다. result_id는 영상 id다.
- `video_subscribe_click` `{ slot }`
- `video_test_click` `{ slot }`: 영상 칸·피드의 "나는 누구 닮았을까?" 클릭이다. 기존 `next_test_click`(같은 사진으로 다음 테스트)과는 뜻이 달라서 새로 만든다.

주의: `SAFE_VALUE` 정규식은 `-`를 막는다. 영상 id(`R-lrShfZU7s`)는 `-`를 `_`로 바꿔 보낸다. 11자라 24자 제한 안에 든다. 정규식 자체를 바꾸지는 않는다.

채널 프로필 링크는 사용자가 유튜브 스튜디오에서 직접 건다. 주소는 `https://unse-ai.com/samguk/videos?utm_source=youtube&utm_medium=profile&utm_campaign=channel`.

## 정해진 것 / 빌더 몫

정해진 것(사용자):
- Data API 사용(RSS는 대체 경로로만), 조회수 표시, 열전 안 재생, 영상 모음 페이지.
- 열전에서 관계 인물의 영상도 보여 주고, 등장·관계 인물은 열전 링크로 잇는다.
- 관계는 삼국지 게임 상관도처럼 초상화 칸으로, 접지 않고 보여 준다(시안 방향 승인 2026-11-05).

내 판단(사용자가 아직 따로 보지 않음):
- 격자 + 전체 화면 피드 혼합 방식, 열전 내 칸 순서, 상관도 묶음 순서·색, 결과 화면 엮인 장수 5칸, 결과 화면 카드는 피드로 연결, NEW 배지 24시간, `youtube-nocookie`, 1시간 갱신, 해시태그 정확 일치 + 보정 파일, 하후돈 영상의 조조 열전 노출, 주인공 우선 정렬, 롱폼 제외, RSS 영상은 쇼츠로 간주, `?v=` canonical, 영상 페이지 쿠팡 배너 위치, `video_test_click` 신설.

빌더 몫:
- 컴포넌트 나누기, 결과 화면으로 데이터 넘기는 방식, 피드 스와이프 세부 구현, 테스트 구성(매핑·대체 경로·NEW 배지 경계·`-` 치환은 단위 테스트 필수).
