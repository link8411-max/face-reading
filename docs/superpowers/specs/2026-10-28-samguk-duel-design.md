# 삼국지 일기토 로그라이크 — 설계 문서

작성일: 2026-10-28 (2차: 운세 사이트 통합 반영)
상태: 검토자 확인 완료, 의뢰인 승인 대기

## 1. 한 줄 요약

삼국지3의 일기토 장면을 16비트 도트 감성으로 되살리고, 거기에 포케로그(PokéRogue)식 로그라이크 진행을 붙인 **혼자 하는 웹게임**이다. 장수 한 명으로 시작해 연속 일기토를 벌이고, 이긴 장수를 영입하며, 보상을 골라 강해지다가 지면 처음부터 다시 한다. 영입한 장수는 장수록에 남아 다음 판의 시작 장수가 된다.

**운세 사이트 unse-ai.com의 `/samguk/duel`로 들어간다.** 기존 삼국지 닮은꼴(`/samguk`)·우리 팀 삼국지(`/samguk/team`)와 한 식구이며, 사이트의 초상화·능력치·공유·쿠팡·SEO·통계 기반을 그대로 쓴다.

## 2. 왜 만드는가

- 삼국지3 일기토는 "말 탄 두 장수가 벌판에서 부딪히는" 장면 하나로 기억에 남는다. 그 장면만 떼어내서 반복해서 즐기고 싶다.
- 포케로그가 증명했듯 "한 판 더"를 부르는 로그라이크 구조는 단순한 1대1 전투를 오래 붙잡게 만든다.
- 삼국지 팬 대부분은 코에이 시리즈로 삼국지를 익혔다. 장수 **얼굴 초상**과 **무력·지력 능력치**라는 코에이식 언어를 그대로 쓰면 바로 친숙해진다. 얼굴이 그 느낌이 아니면 호감이 안 간다.
- 운세 사이트는 "한 번 하고 끝"인 테스트뿐이다. 반복해서 돌아오게 하는 콘텐츠가 필요하고, 검색·공유로 새 방문자를 끌어올 면이 넓어진다.

## 3. 목표 / 비목표 / 실패 조건

**목표**
- 일기토 한 판이 "부딪히는 순간"의 연출로 짜릿하다.
- 장수 초상과 스프라이트가 **한 사람이 그린 세트**처럼 보인다.
- 링크 하나로 누구나 설치 없이 브라우저에서 바로 한다. 모바일 세로 화면 우선.
- 한 판 10~20분. 지면 바로 다시 시작하고 싶어진다.
- 한 판이 끝나면 **열전(이야기)**이 남고, 그것이 공유의 얼굴이 된다.
- 검색("삼국지 일기토", "여포 관우 일기토", "삼국지 미니게임")으로 유입된다.

**비목표 (이번에는 안 한다)**
- 내정, 전쟁, 영토 같은 삼국지 본편 요소
- 사람 대 사람 실시간 대전, 계정
- 모바일 앱 포장 (PWA는 사이트에 이미 있음)
- AI 생성 애니메이션 프레임

**실패 조건 (기술적으로 돌아가도 실패)**
- 장수마다 그림 톤이 달라서 세트로 안 보임
- 전투가 글자만 바뀌는 식으로 밋밋함
- 턴마다 고를 이유가 없어서 제일 센 기술만 누르게 됨
- 쿠팡 배너가 플레이를 막음

## 4. 제약

- **운세 사이트 저장소(`face-reading`, Next.js 16 App Router + TypeScript + Tailwind 4)** 안에 만든다. 그 저장소의 CLAUDE.md 규칙(디자인 토큰, 이모지 금지, PageGuide, sitemap, GA `track()` 허용 키, E2E)을 따른다.
- 사이트는 Vercel 정적/서버 혼합이지만 **게임 자체는 서버 없이** 돈다. 진행 저장은 localStorage.
- 그림 예산: PixelLab 무료 체험 40회 중 32회 남음. 이후는 하루 5회 또는 월 12달러 구독. **그림 수를 늘리는 설계는 피한다.**
- PixelLab 무료 체험은 애니메이션 참고 이미지를 64×64까지만 받는다. AI 애니메이션은 유료 전환 전에는 쓸 수 없다.
- 코에이 초상 원본은 저작권이 있어 직접 쓰지 않는다. 사이트의 초상화는 이미 "코에이 오마주"로 새로 생성한 그림이라 그대로 쓴다.

## 5. 이미 있는 것 (face-reading 저장소) — 다시 만들지 않는다

| 자산 | 위치 | 게임에서 쓰는 법 |
|---|---|---|
| **코에이풍 초상화 77장** (1024×1024 jpg, 디더링 질감) | `public/images/samguk/<한글이름>.jpg` | 전투 화면 위 초상, 장수록, 공유 카드. **초상은 새로 뽑지 않는다.** 1024는 크니 게임용으로 256 정도로 줄인 사본을 둔다 *(제 판단)* |
| 장수 데이터 (통솔·무력·지력·정치·매력, 세력, 역할) | `src/lib/samgukDB.ts` | 능력치 그대로. 유형(맹장·기장·지장)·기술·속도만 게임 데이터로 추가 |
| 레트로 게임 카드 디자인 (남색 `bg-navy-game`, 금색 `text-gold-game`, 픽셀 글꼴 `font-pixel`) | `components/samguk/SamgukGameCard` | 전투 화면·결과 화면의 틀 |
| 카카오톡 공유 + 기본 공유 + 링크 복사 | `hooks/useResultShare`, `lib/kakao.ts`, `lib/share.ts` | 열전 공유 |
| OG 미리보기 이미지 생성 | `/api/og/result?kind=…`, `lib/ogQuery.ts` | `kind=duel` 추가 |
| 쿠팡 파트너스 배너·시즌 카드 | `components/CoupangBanner`, `SeasonPicks` | 결과 화면에 배치 |
| GA4 이벤트 | `lib/analytics.ts` `track()` | `test_name=duel`, 허용 키 안에서 |
| SEO 틀 (layout.tsx 메타·JSON-LD, PageGuide 서버 본문, sitemap) | 각 `layout.tsx`, `content/pageGuides.ts`, `app/sitemap.ts` | 새 페이지 체크리스트 그대로 |
| 메뉴·탭 정의 | `content/navigation.ts` | CATEGORIES에 일기토 추가 |

이 덕분에 **"여포 초상이 여포 같지 않다" 문제는 사라졌다.** 사이트의 여포 초상이 이미 그 느낌이다. PixelLab은 **말 탄 스프라이트에만** 쓴다.

참고: 저장소 `docs/backlog.md`에 다른 형태의 "일기토"(친구와 회사생활 능력치로 겨루기) 아이디어가 있다. 이 문서의 일기토는 그와 다른 게임이며, 친구 대전은 15절(나중)에 둔다.

## 6. 한 판의 흐름

1. **시작 장수 선택** — 장수록에 있는 장수 중 1명. 첫 판은 기본 3명(관우·장비·조운) 중 선택. *(제 판단: 유비는 전투력이 낮아 시작 장수에서 뺐다)*
   - 삼국지 닮은꼴 결과에서 들어오면 **그 결과 장수가 시작 장수로 잠금 해제**된다 (`?me=<장수id>`, 허용 목록 밖이면 무시). 운세 사이트와의 연결 고리.
2. **웨이브 진행** — 적 장수가 한 명씩 나온다. 황건적 졸개 → 이름 있는 장수 → 보스(화웅, 동탁, 여포 순)로 점점 강해진다. 1판은 보스 3명을 포함해 **15~20 웨이브**, 보스는 5~7웨이브마다. *(제 판단)*
3. **일기토** — 8절.
4. **승리 후** — 경험치·레벨업 → 이름 있는 장수면 항복 판정(10절) → 보상 3장 중 1장(11절).
5. **패배** — 출전 장수가 전부 쓰러지면 판 종료. 결과 화면 + 열전(12절).
6. **클리어** — 여포를 쓰러뜨리면 판이 끝난다. 승리 화면, 클리어 횟수 기록.

플레이어는 최대 **3명**을 데리고 다닌다. *(제 판단)* 일기토는 1대1.

### 포케로그에서 그대로 가져온 규칙 (의뢰인 결정)
- **교체 가능** — 전투 중 동행 장수로 교체할 수 있다. 교체한 턴은 상대가 공짜로 행동한다.
- **체력 이어짐** — 웨이브 사이에 회복되지 않는다. 쓰러진 장수는 부활 보상 없이는 그 판에서 돌아오지 못한다.
- **보스 후 완전 회복** — 보스를 이기면 전원 완전 회복.

### 적 장수 풀 (제 판단)
- 시작 장수(관우·장비·조운)도 플레이어가 데리고 있지 않으면 적으로 나온다.
- 동행 중인 장수는 적으로 나오지 않는다. 장수록에만 있는 장수는 나올 수 있고 다시 영입할 수도 있다.
- 같은 이름 있는 장수는 한 판에 한 번만. 졸개는 반복.

## 7. 장수 데이터

### 능력치
`samgukDB.ts`의 통솔·무력·지력·매력을 그대로 쓴다 (정치는 안 씀).
- **무력** → 물리 기술 위력 / **지력** → 꾀 기술 위력 / **통솔** → 체력·방어 / **매력** → 항복 영입 확률
- **속도** — 코에이에 없는 값이라 게임 데이터에 숨은 수치로 둔다. 유형 기본값(기장 높음, 맹장 중간, 지장 낮음) + 장수별 보정. 명마 보상이 올린다. *(제 판단)*

### 유형 — 삼각 상성
| 유형 | 느낌 | 기술 위력의 뿌리 | 이기는 상대 |
|---|---|---|---|
| 맹장(猛) | 힘으로 짓누름 | 무력 | 기장 |
| 기장(技) | 빠르고 정교한 무예 | 무력 + 속도 | 지장 |
| 지장(智) | 허를 찌르는 꾀 | 지력 | 맹장 |

상성 1.5배, 역상성 0.67배. *(제 판단)*

### 1차 장수 명단
사이트에 **초상이 이미 있는** 장수 중에서 고른다. 스프라이트 1장씩만 뽑으면 된다.

| 장수 | 유형 | 역할 | 비고 |
|---|---|---|---|
| 관우 | 맹장 | 시작 장수 | 스프라이트 기준점 (생성 완료) |
| 장비 | 맹장 | 시작 장수 | |
| 조운 | 기장 | 시작 장수 | |
| 마초 | 기장 | 영입 가능 | |
| 황충 | 기장 | 영입 가능 | 활 기술 |
| 허저 | 맹장 | 영입 가능 | |
| 하후돈 | 맹장 | 중간 보스 / 영입 | |
| 주유 | 지장 | 영입 가능 | 화계 |
| 강유 | 지장 | 영입 가능 | 무력도 있음 |
| 화웅 | 맹장 | 보스 1 | 영입 불가. **초상 없음 → 새로 필요** |
| 동탁 | 지장 | 보스 2 | 영입 불가 |
| 여포 | 맹장 | 최종 보스 | 영입 불가 |
| 황건적 졸개 | 맹장 | 잡몹 | 초상 없음(졸개 표시), 스프라이트 1장 색 바꿔 돌려씀 |

화웅은 사이트 초상이 없다. **구현 계획에서 보스 1을 장각(지장, 초상 있음)으로 결정했다** — 황건적 졸개 웨이브의 우두머리라 서사도 맞는다. 화웅은 2차 명단으로.

*(명단·유형·보스 배치는 제 판단. 의뢰인이 바꿀 수 있다.)*

## 8. 일기토 전투

- 1대1 턴제. 매 턴 기술 4개 중 하나 또는 교체. 속도 순으로 행동.
- 장수마다 기술 4개: 기본 공격 1 + 고유 필살기 1~2 + 공용 기술 1~2. 기술에 유형이 있고 **자기 유형 기술은 1.2배** *(제 판단)*.
- 지장의 기술은 지력으로 계산: 화계(지속 피해), 혼란(다음 행동 실패 확률), 매복(반격), 도발.
- 공용 기술: 버티기, 호통, 숨 고르기.
- 고유 필살기 예: 관우 "청룡언월도 참", 장비 "장판교 호통", 조운 "칠진칠출", 여포 "방천화극 난무", 주유 "적벽 화계". 필살기에는 횟수 제한이나 쿨타임.
- 적 AI: 상성과 남은 체력을 보는 단순 규칙. *(빌더)*
- 피해 출발점: `기술 위력 × (공격 능력치 / 상대 통솔) × 상성 × 자속 × 난수(0.85~1.0)` *(빌더가 조정)*

## 9. 화면과 연출

### 화면 — 삼국지3 일기토 구도, 사이트 레트로 카드 톤
- **위**: 양쪽 초상(사이트 초상화) + 이름 + 유형 + 체력 게이지. 플레이어 왼쪽, 적 오른쪽.
- **가운데**: 벌판 배경 위 말 탄 두 장수가 옆모습으로 마주 봄. 적은 좌우 반전. Canvas 2D, 내부 해상도 작게 잡고 정수 배율 *(제 판단)*.
- **아래**: 기술 4개 + 교체 버튼 + 메시지 창.
- 색·글꼴은 `bg-navy-game`/`text-gold-game`/`font-pixel` 등 사이트 토큰. 이모지 금지.
- 모바일 세로 우선. 게임 영역은 `"use client"`, 그 아래 서버 렌더 본문(PageGuide)이 온다.

### 애니메이션 — 코드 연출이 기본
장수 그림은 1장이고 모든 동작은 코드로 만든다 (삼국지3도 그랬다).
- 대기 들썩임 / 공격 돌진 → 충돌 순간 불꽃·흰 번쩍임·화면 흔들림 → 복귀 / 피격 흰 번쩍·뒤로 밀림·피해 숫자 / 쓰러짐·항복 연출
- 필살기: 화면 어두워짐 → **초상 컷인** 크게 → 기술별 효과(초록 초승달 검기, 큰 흔들림, 연타 숫자, 잔상)
- 레벨업 반짝임, 보상 카드 뒤집기
- 효과음은 Web Audio로 합성한 칩튠 풍. 배경음은 나중. *(제 판단)*
- 구조는 **스프라이트 시트 + 동작별 프레임 번호**. 지금은 전부 프레임 1장. 나중에 프레임을 추가해도 코드가 안 바뀌게.

## 10. 영입 (항복)
- 이름 있는 적을 쓰러뜨리면 항복 판정. 확률 = 기본 + 선두 장수 매력 보정 − 상대 등급 보정 *(빌더)*.
- 성공 시 동행 합류(3명 초과면 교체) + **장수록 영구 기록**.
- 보스는 영입 불가, 격파 기록만.

## 11. 보상 (웨이브 사이)
카드 3장 중 1장: 명마(속도), 명기(특정 장수 공격), 병법서(지력·꾀 기술), 회복약, 부활약, 새 공용 기술, 동행 자리 +1(1회). 등급·확률·목록은 빌더.

## 12. 열전(列傳) — 한 판의 이야기와 공유

- 판이 끝나면(클리어·패배) 그 판을 **삼국지 열전 문체**로 자동 생성한다. AI 호출 없이 문장 틀에 기록을 끼운다.
  > 관우, 황건적을 셋 베고 나아가다. 다섯째 싸움에서 화웅을 세 합 만에 베니 사기가 올랐다. 조운이 항복하여 합류. 열한째 싸움, 동탁에게 장비가 쓰러졌으나 관우가 청룡언월도 참으로 끝을 냈다. 열일곱째 싸움, 여포와 마주하다. 아홉 합 끝에 관우가 쓰러지니, 여기서 행군이 끝나다.
- 재료: 웨이브별 상대·턴 수·결정타 기술, 영입·전사, 고른 보상, 클리어 여부. 문장 틀은 처음 10~20개, 나중에 늘린다. *(제 판단)*
- **공유**: 사이트의 `useResultShare` 그대로. 카카오 카드 = 선두 장수 초상 + 한 줄 요약("관우, 열일곱째 싸움에서 여포에게 아홉 합 끝에 쓰러지다") + 도달 웨이브. 착지 페이지 `/samguk/duel/r/[key]` (noindex, canonical은 `/samguk/duel`). 링크에는 개인 정보 없이 결과 키만. OG `kind=duel`.
  - 착지 페이지가 열전 전체를 보여 주려면 링크에 기록을 담아야 한다. 짧은 인코딩(장수 id 열 + 웨이브 요약)을 쿼리에 넣는 방식 *(빌더가 설계, `ogQuery.ts` 허용 목록 규칙 준수)*.
- **행군 기록**: 지난 판들의 열전을 localStorage에 남겨 장수록 옆 "행군 기록" 탭에서 다시 읽는다. 클리어한 판은 특별 표시.

## 15. SEO
- `/samguk/duel/layout.tsx`: 메타·OG·canonical·JSON-LD(VideoGame 또는 SoftwareApplication) + `<PageGuide route="/samguk/duel">`. 본문: 일기토란, 놀이 방법, 상성 설명, 장수 소개, FAQ.
- **장수별 페이지** `/samguk/duel/generals/[id]` (정적 생성): 초상 + 코에이식 능력치 + 유형 + 기술 + 한 줄 열전 + "이 장수로 시작". 검색 면을 넓히는 핵심. 얇은 콘텐츠가 되지 않게 장수당 본문 분량 기준을 둔다 *(빌더)*.
- sitemap `SITEMAP_ROUTES`·`LAST_MODIFIED` 추가. 착지 페이지(`/r/`)는 noindex·사이트맵 제외.
- 네이버 서치어드바이저·구글 서치콘솔에 새 URL 수집 요청(의뢰인 작업).
- **첫 알림 채널**: 의뢰인이 침하하에 올린 "얼굴로 삼국지 장수 찾아 주는 거 만들어 봄" 글(https://chimhaha.net/best/934378)에 업데이트 소식으로 붙인다. 그 글의 반응("누가 이김?" 류)을 보고 친구 대전(21절)을 당길지 정한다.

## 16. 플레이어 피드백
- 결과 화면에 "이 판 어땠어요?" — 별점(1~5) + 한 줄 글(선택) + 자동 첨부(도달 웨이브, 선두 장수, 클리어 여부, 기기 종류). 사진·개인정보 없음.
- 저장: **Supabase 테이블** (의뢰인 계정 있음) — Next.js API route가 서버 키로 insert. 저장소에 Supabase가 아직 없으므로 빌더가 추가한다. 실패해도 게임은 멈추지 않는다. *(제 판단. Google Form으로 바꿀 수 있음)*
- 의뢰인은 Supabase 대시보드에서 본다. 별도 관리 화면은 만들지 않는다.

## 19. 기술 선택 (제 판단)
