# 삼국지 인물열전·관계도·응원 순위 설계

2026-11-03. 사용자와 대화로 정한 내용. "내 판단"이라고 적은 곳은 사용자가 따로 정하지 않아 설계자가 정한 부분이다.

## 왜 만드나

- 네이버에서 장수 이름 검색에 우리 페이지가 이미 노출된다. 예: "하후돈" 검색에 일기토 장수 페이지가 451회 노출, 클릭 1회(30일, 11/2 기준).
- 이름을 검색한 사람은 인물 정보를 원한다. 게임 공략처럼 보이는 페이지는 누르지 않는다.
- 사람들이 원하는 인물 정보를 주는 열전 페이지를 만들고, 그 위에서 닮은꼴 테스트·일기토·참여 기능으로 이어지게 한다.
- 네이버 자동완성 기준 실제 검색어(2026-11-03):
  - 하후돈: 뜻, 무기, 원양(자), 묘·무덤
  - 여포: 뜻, 명언, 무기, 초선
  - 관우: 무기, 관운장, 유비 관우 장비
  - 제갈량: 뜻, 출사표, 제갈공명
  - 삼국지 인물: 관계도, 소개, 실존, 순위, 이름, 테스트
- 애드센스 심사의 약점("글이 적다")도 줄인다.

## 목표

1. 장수별 인물열전 페이지. 검색에서 인물 이름으로 들어와 누르고 싶은 제목과 내용.
2. 전체 인물 관계도 페이지("삼국지 인물 관계도" 검색 대상).
3. 응원 순위 페이지("삼국지 인물 순위" 검색 대상).
4. 열전에서 참여: 응원, 가상 대결 투표, 명장면 투표, 한 줄 평 고르기.
5. 닮은꼴 결과와 열전을 서로 연결.
6. 검색 연결: 사이트맵, 네이버 수집 요청, 구글 색인 요청, 일기토 장수 페이지에서 열전 링크.
7. MBTI 유형 16개 페이지의 검색 제목·설명 개선(별도 작은 작업, 아래 "MBTI" 절).
8. 나중에 이어 쓸 수 있게 진행 목록을 남긴다.

## 목표가 아닌 것

- 자유 댓글. 쿠키만으로는 차단이 안 되고 애드센스에 위험해서 이번에는 넣지 않는다. 반응을 보고 카카오 로그인과 함께 따로 설계한다.
- 로그인, 회원 기능.
- 싫어요 버튼.
- 첫 공개에서 93명 전원 열전 작성.

## 하면 안 되는 것 (실패로 본다)

- 사실이 아닌 내용. 정사와 연의를 섞어 정사처럼 쓰는 것.
- 나무위키·위키백과·책 문장을 그대로 또는 살짝 바꿔 옮기는 것.
- 가짜 숫자. 응원 수·투표 비율은 실제 집계만 보여 준다(기존 규칙: 실제 집계 전 숫자 금지). 집계가 적을 때는 숫자를 숨기거나 "아직 투표가 적어요"로 보여 준다.
- 스크롤 압박. 긴 글을 펼친 채 나열하지 않는다.
- IP 원본 저장.

## 페이지

### 1. 인물열전 `/samguk/people/[id]` (A안, 사용자 선택)

id는 `samgukDB.ts`의 영문 id를 그대로 쓴다(예: `xiahoudun`이 아니라 DB의 실제 id를 확인해서 사용).

위에서 아래 순서:

0. **쿠팡 다이나믹 배너(최상단, 사용자 결정 2026-11-03)**: `CoupangBanner`, subId `people-<id>`. 대가성 문구 포함.
1. **닮은꼴 배너(쿠팡 배너 바로 아래)**: "나도 하후돈을 닮았을까? 사진 한 장으로 확인하기" → `/samguk`. 일기토에 나오는 장수면 두 번째 버튼 "일기토에서 싸워 보기" → `/samguk/duel?me=<duel id>`.
2. **머리 카드**: 초상화(없으면 "초상화 추가 예정" 자리), 소속 세력·역할, 이름·한자·자(字), 생몰년·출신지.
3. **요약 2~3줄**과 **특징 태그** 3~5개.
4. **한눈에 보기 칸**: 이름 뜻·자, 무기(연의/정사 구분), 대표 명언. 검색어(뜻·무기·명언) 대응.
5. **응원 버튼 + 응원 수**.
6. **접힌 항목**(`details`, 눌러서 펼침. 글은 HTML에 남아 검색에 잡힘):
   - 생애 열전(최후와 묘 포함)
   - 주요 전투(전투 이름, 연도, 역할 한 줄씩)
   - 관계도·혈연(아래 "관계 데이터")
   - 정사와 연의의 차이
7. **가상 대결 투표**: 라이벌 한 명과 "일기토하면 누가 이길까?" 투표 → 비율 공개, 공유 버튼.
8. **명장면 투표**: 주요 전투·일화 3~4개 중 하나 선택 → 비율.
9. **한 줄 평 고르기**: 정해진 말 중 하나(예: 충신, 과대평가, 저평가, 의리). 많이 고른 말은 머리 카드 태그 옆에 표시.
10. (쿠팡 배너는 0번 최상단으로 옮김)
11. **함께 보는 인물**: 관계 데이터의 인물들 열전 링크(없는 열전은 링크 없이 이름만).
12. 기존 공통 하단(PageGuide 형식의 FAQ는 선택, 내 판단으로 생략 가능).

검색 메타:
- 제목: `하후돈 열전 | 자 원양, 뜻·무기·관계도 – 운명을 읽다` 형식. 48자 이하(기존 `tests/seo-snippets.test.tsx` 규칙), 인물 이름으로 시작, 브랜드 한 번.
- 설명: 요약 + 검색어(무기, 관계, 최후) 포함 50~160자.
- canonical, OG(기존 `/api/og/result?kind=samguk` 도트 초상화 활용 가능), JSON-LD `Person`(name, alternateName=자·한자, birthDate/deathDate는 연도만, affiliation).

### 2. 인물 관계도 `/samguk/people`

- 열전 목록 허브를 겸한다. 세력별(위·촉·오·기타) 인물 카드, 열전이 있는 인물은 링크.
- 관계도: 세력별 주요 인물과 관계선(군신, 의형제, 혈연, 혼인, 라이벌). 모바일에서 읽히게 세력별로 접는 방식 허용.
- 그림 아래에 관계를 글 목록으로도 적는다("유비·관우·장비: 도원결의 의형제"). 검색 로봇은 그림을 못 읽는다.
- 제목: `삼국지 인물 관계도 | 위·촉·오 인물 소개 – 운명을 읽다` 형식.

### 3. 응원 순위 `/samguk/people/ranking`

- 전체 순위와 세력별 순위(응원 수 기준). 각 줄은 열전 링크.
- 집계가 적을 때(내 판단: 전체 응원 30회 미만) 순위 대신 "응원을 모으는 중"과 인물 목록을 보여 준다.
- 서버 렌더(ISR, 내 판단: 1시간)로 순위 글이 HTML에 들어가게 한다.
- 제목: `삼국지 인물 순위 | 가장 응원받는 장수 – 운명을 읽다` 형식.

## 콘텐츠 데이터

- 파일: `src/content/samgukPeople/` 아래 인물별 TS 파일 또는 한 파일(구현자 판단). `samgukDB.ts`는 닮은꼴용이라 건드리지 않고 id로 연결한다.
- 인물별 필드(초안):
  - id, 자(字), 생몰년(모르면 "?"), 출신지
  - summary(2~3줄), tags
  - nameMeaning(이름·자 뜻), weapon({ novel, history }), famousQuote({ text, source: 정사|연의 })
  - life(생애 열전, 최후·묘 포함, 600~1,200자 내 판단)
  - battles: [{ name, year, role, source }]
  - relations: [{ id 또는 name, type: 군신|의형제|부자|형제|부부|혼인|사촌|라이벌|원수, note, source }]
  - novelVsHistory(정사와 연의 차이 2~4개)
  - rivalId(대결 투표 상대), sceneOptions(명장면 3~4개), verdictOptions(한 줄 평 선택지, 공통 목록에서 고름)
- 사실 기준: 진수 『삼국지』(정사)와 배송지 주, 나관중 『삼국지연의』. 모든 전투·관계·명언에 정사/연의 표시를 단다. 확실하지 않은 사실은 쓰지 않는다.
- 글은 새로 쓴다. 다른 사이트 문장 복사 금지.
- 작성 후 사실 검토 단계를 반드시 거친다(아래 "검증").

## 관계 데이터

- 열전의 relations에서 관계도를 만든다. 양방향 관계는 한쪽만 적어도 양쪽에 보이게 한다.
- 혈연(부자·형제·사촌·부부)과 그 밖의 관계(군신·의형제·라이벌)를 구분해 보여 준다.
- 열전 안 관계도: 그 인물 중심 작은 그림 + 글 목록. 전체 관계도: 세력별.
- 그림은 SVG(서버 렌더)로 그린다(내 판단, 라이브러리 추가 없이).

## 참여 기능

### 저장

- Supabase(기존 `SUPABASE_URL`·`SUPABASE_SERVICE_KEY`, 일기토와 같은 프로젝트). 새 테이블 SQL은 `docs/people-votes.sql`로 두고 사용자가 SQL Editor에서 실행한다.
- 테이블(초안): `people_votes(kind, target, option, voter_hash, day, created_at)`. kind: cheer|duel|scene|verdict.
- 중복 막기: 기기 쿠키의 무작위 id와 IP를 서버에서 날마다 바뀌는 비밀 값과 섞어 해시. 응원은 인물마다 하루 1회, 투표는 항목마다 1회(다시 누르면 바꾸기, 내 판단). IP 원본·쿠키 원본은 저장하지 않는다.
- API: `/api/people/vote`(POST), 집계는 `/api/people/stats?id=`(GET, CDN 캐시 짧게) 또는 서버에서 직접.
- 환경 변수가 없으면 버튼은 보이되 "잠시 후 다시" 처리 없이 조용히 실패하지 않게, 집계 숫자 영역을 숨긴다(일기토 API와 같은 태도).
- 개인정보처리방침에 응원·투표 기록(해시) 안내 한 줄 추가.

### 화면 규칙

- 투표 전에는 비율을 숨기고, 투표하면 비율이 열린다.
- 집계 수가 적으면(내 판단: 10표 미만) 비율 대신 "아직 투표가 적어요".
- 공유: 대결 투표 결과를 `useResultShare` 흐름으로 공유("하후돈 vs 허저, 나는 하후돈. 너는?"), 링크는 열전 주소 + utm(source=share).
- GA 이벤트: 기존 `track()` 허용 키만. 예: `people_cheer(result_id=<id>)`, `people_vote(result_id=<kind>_<id>)`. 새 이벤트 이름은 analytics.ts 타입에 추가.

## MBTI 검색 제목·설명 (별도 작은 작업)

- 문제: 별명 검색("용감한 수호자 isfp" 등)에 노출은 많고 클릭이 적다(예: ESFP 258 노출 3 클릭).
- 바꿀 것: `/mbti/[type]` 16개 제목을 "ISFP 특징·궁합 순위 | 호기심 많은 예술가 – 운명을 읽다" 형식으로, 설명은 "잘 맞는 유형 1위"처럼 궁금증을 주는 문장으로. 48자 규칙 지킴.
- 페이지 위쪽에 사진 테스트로 가는 연결 한 줄("내 얼굴은 무슨 상일까?" → `/face2` 또는 `/animal`, 내 판단).
- 이 작업은 열전과 독립이라 먼저 끝내도 된다.

## 검증

- 단위 테스트: 열전 데이터 형식(필수 필드, 관계 id가 실제 인물, 정사/연의 표시 누락 없음, 제목 48자 이하), 관계 양방향 처리, 투표 해시·중복 규칙.
- 사실 검토: 열전마다 별도 검토 단계에서 전투 연도·관계·최후를 정사 기록과 대조. 확인 못 한 줄은 지운다. 진행 목록에 "사실 검토" 칸 체크.
- E2E: 열전 페이지 로딩, 펼치기, 배너 링크, 응원 버튼(환경 변수 없는 E2E에서는 숫자 숨김 확인), 관계도·순위 페이지, 이모지 금지 규칙.
- 배포 후 실제 페이지 제목·canonical 확인, 사이트맵 포함 확인.
