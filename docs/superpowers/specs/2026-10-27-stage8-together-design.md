# 8단계: 함께 하는 테스트 — 얼굴 궁합, 우리 팀 삼국지

작성: 2026-10-27. 상위 문서 `2026-10-26-unse-ai-revival-design.md`의 "8단계"를 구체화한다.

## 왜 하나
- 수익(애드센스·쿠팡)은 방문과 페이지뷰에서 나온다. 혼자 하는 테스트는 한 번 하고 끝나지만, 둘·여럿이 하는 테스트는 **다른 사람을 데려온다**.
- 이미 만든 기반: 결과별 공유 링크와 미리보기(`lib/shareLinks.ts`, `/…/r/…`), 카카오톡 공유(`lib/kakao.ts`), 동물상·삼국지 매칭(MediaPipe, 성별 기준값).
- 사용자가 꼽은 장면: 친구끼리, 커플끼리, 그리고 **짝사랑**(상대는 모르게 내가 사진을 올림).

## 목표 / 비목표 / 반목표
- 목표
  - 얼굴 궁합: 두 얼굴의 궁합을 관계(친구·연인·짝사랑)별로 보여준다.
  - 우리 팀 삼국지: 2~6명의 얼굴로 팀의 세력과 역할을 만든다.
  - 두 기능 모두 결과를 링크로 공유하면 받은 사람이 "나도 해보기"로 들어온다.
- 비목표
  - 서버 저장, 회원가입, 여러 기기 실시간 연동
  - 링크에 이름·사진·얼굴 수치를 담는 것(결과 유형 키와 관계만 담는다)
- 반목표(이렇게 되면 실패)
  - 낮은 점수가 상처가 되는 문구("최악", "안 맞음")
  - 남의 사진을 저장하거나 서버로 보내는 것
  - 같은 두 사람인데 들어온 경로(한 폰/초대 링크)에 따라 점수가 다른 것

## 사용자가 정한 것
- **두 가지 방식을 모두 만든다.**
  - 한 폰에서 사진 두 장: 같이 있을 때, 그리고 짝사랑(상대는 테스트를 안 함)
  - 링크 초대: 내 결과에서 친구에게 링크를 보내고, 친구가 자기 사진으로 테스트하면 둘의 궁합이 나온다. 유입을 늘리는 핵심이다.
- **관계를 먼저 고른다**(친구·연인·짝사랑). 결과는 고른 관계의 점수와 문구를 크게 하나, 아래에 다른 관계 점수를 작게 보여준다.
- **궁합은 각 얼굴의 동물상 결과로 계산한다**(예: 고양이상 × 강아지상). 링크에는 결과 유형만 담을 수 있으므로, 한 폰이든 초대든 같은 규칙으로 같은 점수가 나오게 하려는 것이다.

## 얼굴 궁합 (새 페이지 `/face-match`)
### 흐름
1. **관계 고르기**: 친구 · 연인 · 짝사랑 (pill 3개, 필수)
2. **사진 두 장** (한 폰 방식)
   - 칸 이름은 관계에 따라 바꾼다: 친구 "나 / 친구", 연인 "나 / 내 사람", 짝사랑 "나 / 그 사람"
   - 칸마다 성별 pill(필수)과 사진 영역. 각 얼굴은 기존 동물상 매칭(성별 기준값)으로 동물상을 구한다.
   - 사진 안내 문구를 버튼 바로 위에 두고, 짝사랑일 때는 "상대 사진도 내 폰 안에서만 보고 바로 지워요. 어디에도 올라가지 않아요"를 크게 보여준다.
3. **결과 카드**(캡처 한 장 완결, 워터마크)
   - 두 동물상 이름과 고른 관계의 점수를 크게 보여준다. 짝사랑은 "성공 가능성 82%" 같은 표현을 쓴다.
   - 잘 맞는 이유 두 줄과 다른 관계 점수(작게)
   - 버튼: 공유하기(1순위), 이미지 저장, 다시하기

### 링크 초대
- 진입: 동물상 결과 화면의 2순위 버튼 "친구 얼굴이랑 궁합"(4b에서 보류했던 자리), 홈 "친구랑 같이 해봐요" 4번째 칸(지금 MBTI 궁합 자리를 얼굴 궁합으로 바꾼다. MBTI 궁합은 하단 "궁합" 탭에 남는다).
- 초대 링크에는 내 동물상 키와 관계만 담는다. 예: `/face-match/i/cat?rel=lover`
- 받은 사람 화면
  - "친구가 얼굴 궁합을 신청했어요 (친구는 고양이상)"를 보여준다.
  - 받은 사람은 자기 성별과 사진을 넣고 결과를 본다.
  - 그 자리에서 "결과 보내 주기"(공유하기)로 되돌려 보낸다.
- **짝사랑은 초대 링크를 만들지 않는다**(상대에게 보내는 순간 짝사랑이 아니다). 짝사랑 결과의 공유는 "나 짝사랑 궁합 82% 나왔어. 너도 해볼래?"처럼 친구에게 자랑하는 용도다.

### 결과 공유 링크
- `/face-match/r/[a]-[b]?rel=…&utm…` (a, b = 동물상 키). 착지 화면은 "친구가 본 얼굴 궁합: 고양이상 × 강아지상, 연인 궁합 87점"과 "나도 해보기"를 보여준다. 검색 제외(noindex), canonical은 `/face-match`, 사이트맵 제외.
- 미리보기 이미지: `/api/og/result?kind=face-match&a=&b=&rel=`

### 점수 규칙
- 동물상 8×8 쌍 × 관계 3가지. 대칭(a×b = b×a), 결정적.
- 기준은 `animalTypeDB`의 best/worst다.
  - best 쌍은 높게 준다.
  - worst 쌍도 "서로 배우는 사이"로 중간 이상을 준다.
  - 같은 동물상끼리는 친구로는 높고 연인으로는 중간이다.
- 범위는 55~100이다. MBTI 궁합처럼 관계마다 가장 잘 맞는 쌍은 정확히 100점이다(사용자가 MBTI 때 "최대 100까지 나와야지 사람들 심리를 생각해"라고 했다).
- 문구는 점수 구간별 긍정형 라벨이다(천생연분 / 찰떡 / 좋은 짝 / 서로 배우는 사이 / 노력하면 빛나는 사이). 짝사랑은 "가능성" 표현을 쓴다.

## 우리 팀 삼국지 (새 페이지 `/samguk/team`)
### 흐름
1. 인원: 2~6명. 처음에 2칸, "한 명 더" 버튼으로 늘린다.
2. 칸마다: 별칭(선택, 화면과 저장 이미지에만 쓰고 링크에는 넣지 않음), 성별 pill(필수), 사진. 각 얼굴은 기존 삼국지 매칭으로 장수를 구한다.
3. **팀 결과**(게임 카드 톤, 남색)
   - 팀원별 미니 카드: 도트 초상화, 장수 이름, 별칭
   - 팀 역할 자동 배정: 군주(통솔·매력 최고), 책사(지력), 선봉장(무력), 살림꾼(정치). 남는 사람은 "든든한 장수".
   - 팀의 기운: 가장 많은 세력("우리 팀은 촉나라 기운"), 동수면 "천하삼분"
   - 팀 회사생활 STATUS(funStats 평균), 한줄평(규칙 기반 문장)
   - 버튼: 공유하기, 이미지 저장, 다시하기
- 진입: 삼국지 결과 화면 1순위 버튼 "우리 팀 삼국지 만들기"(4b에서 보류한 자리). 상단 버튼 순서는 이 버튼 → 공유하기 → 이미지 저장.

### 결과 공유 링크
- `/samguk/team/r/[id1-id2-…]?utm…` (장수 id 2~6개, 허용 목록 검증). 별칭은 넣지 않는다. 착지 화면은 팀 구성과 "우리 팀도 만들어 보기"를 보여준다. 검색 제외, 사이트맵 제외.

## 공통 제약
- 사진은 브라우저 안에서만 분석하고 저장하지 않는다(MediaPipe, 기존 파이프라인 재사용). 한 화면에서 여러 장을 차례로 분석한다.
- 정면이 아니거나 얼굴이 없는 사진은 그 칸에만 안내하고, 다른 칸은 그대로 둔다.
- GA 이벤트: `test_name`에 `face_match`, `team_samguk` 추가. 기존 이벤트(test_start, result_view, share_click, shared_landing)를 그대로 쓴다. `result_id`는 유형 키 조합만 넣는다(예: `cat_dog_lover`, `zhaoyun_caocao`).
- 디자인은 4b 뉴트럴 토큰과 공통 구성요소를 쓴다(TestHeader, GenderPills, PhotoPicker 계열, ResultActions, 공유 훅).
- URL은 새로 만들고 기존 URL은 바꾸지 않는다.

## 검토 후 정한 세부 (제안자 결정)
- **동물상 결과의 "친구 얼굴이랑 궁합"**
  - 누르면 `/face-match`로 넘어간다. "나" 칸에는 내 동물상 결과가 이미 채워져 있다(쿼리 `?me=cat`, 사진은 다시 받지 않음).
  - 여기서 관계를 고르고 두 방법 중 하나를 쓴다.
    - "그 사람 사진 올리기": 한 폰 방식
    - "친구에게 초대 링크 보내기": 친구·연인만. 짝사랑을 고르면 이 버튼은 숨긴다.
  - 한 폰 결과 화면에는 초대 버튼을 두지 않고, 결과 공유만 둔다.
- **팀 역할 배정**
  - 한 사람은 역할 하나만 맡는다.
  - 채우는 순서: 군주(통솔+매력) → 책사(지력) → 선봉장(무력) → 살림꾼(정치)
  - 각 역할은 남은 사람 중 해당 능력치가 가장 높은 사람이 맡는다. 동점이면 먼저 올린 사람이 맡는다.
  - 2~3명이면 앞 역할부터 채운다. 5~6명이면 남는 사람은 "든든한 장수"가 된다.
  - 같은 장수가 여러 번 나와도 그대로 둔다(링크에도 중복 허용).
- **팀의 기운**
  - 위·촉·오·기타 중 가장 많은 세력의 이름을 쓴다. 기타가 가장 많으면 "군웅할거의 기운"이다.
  - 위·촉·오가 같은 수로 가장 많으면 "천하삼분"이다. 그 밖에 동수인 경우는 먼저 올린 사람의 세력을 따른다.
- **GA result_id**: 개인정보 필터(24자, 유형 키만)를 그대로 둔다.
  - 팀: 군주 id와 인원수만 보낸다(예: `liubei_4`).
  - 얼굴 궁합: 두 동물상과 관계를 보낸다(예: `cat_dog_lover`).

## 빌더에게 맡기는 것
- 8×8×3 점수표의 구체 값(위 규칙 안에서), 이유 문장, 팀 한줄평 문장
- 화면 세부 배치(4b 시안 톤 안에서)
- 한 폰 두 장 업로드의 정확한 UI(칸 두 개를 나란히 둘지, 차례로 받을지)
