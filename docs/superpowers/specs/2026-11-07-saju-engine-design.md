# 사주 엔진·내 사주 풀이 설계 (2026-11-07)

## 왜
지금 /fortune 신년운세는 년주·월주를 날짜 근사(입춘 2/4 0시 고정, 절기 날짜표)로 잡아 **2027 입춘 당일(2/4 10:46 KST 이전 출생)도 틀리고**, 시주는 계산하지 않으며(입력 문자열을 표시만), 십신·대운·세운이 없다. 풀이 글은 띠별 고정 DB라 엔진이 정확해져도 글이 안 바뀐다. 사용자 요구: "운세·사주도 전문가가 봐도 틀리지 않게, 다양한 데이터로", 그리고 **왜 믿을 수 있는지가 보이게**.

## 결정 (Claude의 판단, 사용자가 "너가 판단해줘")
1. **제품**: 연도와 무관한 **"내 사주 풀이" 페이지 `/saju`**를 새 엔진 위에 만들고, **신년운세 `/fortune`**은 같은 엔진으로 사주 표와 "2027 정미년과 내 사주" 절을 보여 준다(풀이 글 DB는 이번엔 그대로, 2판에서 십신·세운 기반으로 교체).
2. **만세력**: npm `manseryeok@2.0.0`(MIT, 의존성 0, 184KB, 천문연 절기표 1800~2300 분 단위, 한국 서머타임·표준시 변경·야자시 옵션·진태양시 옵션 내장)을 **정확한 버전으로 고정**해 `src/lib/saju/engine.ts` 한 곳에서만 감싼다. 라이브러리 타입은 밖으로 새지 않는다. 서버(API 라우트)에서만 호출하고 클라이언트엔 결과 JSON만 간다. 검증: 1990-05-15 14:30 → 경오·신사·경진·계미, 대운 7세 순행(남)/3세 역행(여), 2027 입춘 10:46 전환, 일주 1940~2010 표본 213건 korean-lunar-calendar와 일치. 중국 `lunar-javascript`는 UTC+8 기준이라 절입 경계 1시간 오판(3,408건 중 년주 5·월주 55 불일치)으로 탈락.
3. **계산 기준(화면에 밝힌다)**: 월주는 12절 절입 **시각** 기준 · 야자시는 `midnight`(밤 11시~12시 출생은 **그 날짜의 일주**, 시주는 자시) · 진태양시 보정 **안 함**(사용자 입력이 2시간 단위라 켜면 더 헷갈림) · 1948~51·1955~60·1987~88 서머타임과 1954~61 UTC+8:30은 **자동 반영**(라이브러리 `applyHistoricalDst`, 경도 135로 경도 보정 0). 경계(절입 ±1시간, 23시~1시)면 "보는 방식에 따라 달라질 수 있어요" 한 줄.
4. **입력**: 양력/음력(윤달) 생년월일(기존 `BirthDateFields`), 태어난 시간 select(12지시 + "모름". **자시는 "밤 11~12시"와 "밤 12~1시" 두 칸**으로 나눠 날짜 경계 모호함 제거. 엔진엔 각 칸의 가운데 시각을 넘김), **성별**(대운 순·역행에 필요. `genderMemory` 재사용, 기억값 미리 선택). 시간 "모름"이면 **세 기둥**으로 풀고 상단에 "시간을 알면 시주까지 봐요".
5. **결과에 넣는 것**(순서): ① 사주 표(4열, 한자+한글, 시주 모름이면 "모름" 열) ② "나는 ○○이에요"(일간 10종 비유 한 줄) ③ 오행 분포 막대(천간 4 + 지지 정기 4 = 8글자, 시주 없으면 6) ④ 십신 요약 상위 2(쉬운 이름, 전통 이름 작게, 근거 꼬리 "정재가 둘이라") ⑤ 대운 타임라인(10년 단위 8구간, 시작 나이, 현재 구간 강조, 세는 나이 표기) ⑥ 2027 정미년과 나(일간×정 십신 + 일지×미 관계 등급) ⑦ 조심할 점 하나(과다·부재 오행 → 상황형 + 행동) ⑧ "어떻게 계산했나요"(접이식) ⑨ 고지·출처.
6. **넣지 않는 것**: 용신·격국 단정, 신살(백호·괴강·고란·과부·원진·귀문·공망·양인·천라지망 생략; 역마·도화는 이번 판에 아예 안 씀), 관살혼잡·상관견관·재다신약 같은 조합 판정, 신강/신약 단정, 궁합 점수, 건강·수명·결혼 예언, 나이별 사건 예언.
7. **공유**: 생년월일·성별·사주 글자는 링크·이미지·GA에 넣지 않는다(기존 정책). 공유 착지는 **일간 10종** `/saju/r/<일간 영문키>`("나는 갑목이래. 너는?") — 사주 표는 착지에 없음. 결과 캡처(`useScreenshot`)는 사주 표를 포함하되 생년월일 줄은 `no-screenshot`.

## 신뢰 장치 (사용자 요청: "왜 믿을 수 있는지 노출")
- **사주 표를 숨기지 않는다.** 다른 만세력 앱과 같은 여덟 글자가 보이는 게 가장 강한 신뢰.
- **"어떻게 계산했나요" 접이식** 4줄: 절기 시각 기준 월주 / 야자시 처리 / 서머타임·표준시 반영 / 진태양시 미적용. 경계면 안내 한 줄 추가.
- **문장마다 근거 꼬리**: "정재가 둘이라 돈을 꾸준히 모으는 쪽으로 풀어요"처럼 해석 뒤에 글자 근거. 근거 없는 문장 금지(테스트).
- **전통 이름 병기**: 쉬운 이름 앞, 전통 용어(정재·대운) 작은 글씨.
- **한계 먼저**: 시간 모름 → "세 기둥으로 봤어요" 상단. 대운 나이는 "약 ○세(세는 나이)".
- **출처 한 줄**: "절기·음력은 한국천문연구원 역법 데이터를 담은 만세력 라이브러리 기준이에요. 해석은 유파에 따라 다를 수 있어요."

## 쉬운 말 번역 (문구 파일에 고정, 금지어 테스트 공유)
십신 → 쉬운 이름: 비견 나란히 / 겁재 승부욕 / 식신 즐기는 재주 / 상관 톡톡 표현 / 편재 넓은 활동 / 정재 꼼꼼한 살림 / 편관 도전 압력 / 정관 반듯한 틀 / 편인 특별한 배움 / 정인 든든한 배움. 각각 "많을 때·없을 때" 한 줄은 긍정 프레이밍(연구 보고서 표 채택).
오행 → 새싹(목)·불꽃(화)·대지(토)·칼날(금)·물결(수), 강할 때·약할 때 한 줄.
관계 → 합 "서로 끌어당겨 어우러져요" / 충 "부딪히며 변화가 생겨요" / 형 "마찰이 있지만 다듬는 과정이에요" / 파 "계획이 살짝 틀어질 수 있어 점검" / 해 "사소한 오해, 소통". 일지×미(未): 축 충·오 합·자 해·술 파·묘/해 반합(약)·미 같은 글자·나머지 없음. 강한 관계(충·육합)와 약한 관계(반합·파·해)를 등급으로 나눠 문구 강도도 다르게.
문장 규칙은 관상 2판 "문장 규칙"을 그대로(해요체, 이모지 금지, 금지어·평가어·예언어, 상황형 조심할 점 1개 + 행동 1개).

## 쉬운 말 규칙 추가 (2026-11-07 사용자 결정: "풀이가 더 쉬워야")
- **본문에는 전통 용어 0개.** 십신(정관·편관·인성…)·간지(경금·을유…)·오행 한자·"대운/세운/일간"은 본문 문장에 쓰지 않고 **작은 회색 꼬리 줄**(`basis` 줄)에만 둔다. 테스트로 막는다(본문 필드 문자열에 TEN_GODS·STEMS+오행·"대운·세운·일간·일지" 포함 금지).
- **"그래서 나는 어떤 사람"으로 시작.** 글자 설명이 아니라 행동으로: "한번 정하면 깔끔하게 끊고 가는 편이에요."
- **제목도 쉬운 말.** "나는 ○○ 같은 사람이에요" / "내 사주에서 제일 센 것 두 가지" / "2027년은 나에게" / "지금 10년의 흐름" / "조심할 점 하나" / "어떻게 계산했나요".
- **문장은 둘.** 특징 한 문장 + 어떤 상황에 좋은지 한 문장. 대운은 "37세부터 46세까지는 '돈을 꾸준히 모으는 시기'예요" 식 나이 범위 + 따옴표 한 줄.
- 예시(일간 경, 관성 2·인성 2, 2027 정관, 을유 대운): 본문 "책임감. 맡은 일은 끝까지 해요. 규칙 있는 곳에서 더 잘 돼요." / 꼬리 "관성(정관·편관) 2개".

## 구현 개요
- `src/lib/saju/engine.ts`: `computeSaju(input: SajuInput): Saju` 순수·결정적. 입력 `{ y,m,d, hourSlot: HourSlot|null, isLunar, isLeapMonth, gender, asOfYear }`. 출력: 네 기둥(각 `{ gan, ji, hanja, korean, element, yinYang }`), `dayMaster`, `elements`(5 count), `tenGods`(10 count + 기둥별), `daeun[]`(`{ startAge, ganji, korean, isCurrent }`), `seun`(`{ year, ganji, tenGodToDayMaster, dayBranchRelation: {kind, strength} }`), `basis`(계산 기준 플래그: dst 적용 여부, boundaryWarning).
- `src/lib/saju/hourSlots.ts`: 13칸(자시 둘) → 대표 시각. `src/content/saju.ts`: 일간 10 비유, 십신·오행·관계 문구, 조심할 점 규칙 문구, 계산 기준 문구, 고지.
- `src/app/saju/` 페이지(입력 → `/api/saju` POST → 결과), `components/saju/{SajuTable,ElementBars,DaeunTimeline,SajuResultView}.tsx`, 공유 착지 `/saju/r/[key]` + og.
- `/fortune`: 서비스가 엔진을 호출해 사주 표·세운 절만 교체(FortuneClient 상단). `saju.ts`의 `년주계산`·`일주계산`은 일진 엔진이 쓰므로 시그니처 유지하되 내부를 엔진으로 바꾼다(테스트 `tests/saju.test.ts`의 2027-02-04 단언은 시각 포함으로 수정).
- 문구·테스트 정합: `pageGuides.ts` /fortune 설명("여섯 글자", "하루 정도", "시간을 몰라도 결과가 같아요")과 `tests/pageGuides.test.ts`의 역단언을 **같은 커밋에서** "네 기둥·절기 시각" 기준으로 바꾼다. CLAUDE.md "신년운세" 절 갱신.
- 테스트: 골든 케이스(1990-05-15 14:30 남/여, 2027-02-03 12:00·02-04 05:00·02-04 12:00, 1988-07-01 00:30 서머타임, 1990-05-15 밤 11시 반/12시 반, 음력 1990-4-21=양력 5-15, 윤달), 결정성(같은 입력 두 번), 십신 count 합 = 글자 수−1, 대운 방향 규칙(양남음녀 순행), 문구 금지어, 근거 꼬리 존재.
- 출시 전 사용자 점검: 본인·가족 생년월일시 3건을 포스텔러·원광만세력과 사주 표가 같은지 대조(Claude가 대신 할 수 없는 확인).

## 빌더 검토 뒤 정한 것 (Claude의 결정)
- **시각 없는 호출**: `년주계산(y, m, d, hour = 12)`·`월주계산(...)`에 선택 인자 `hour`를 더하고 기본값은 **정오**. 일진 엔진(`dailyEngine/index.ts:69`)·띠찾기·푸시는 지금처럼 날짜만 넘기므로 정오 기준(입춘 당일 출생자는 정오 기준 년주). 일진 분포 테스트는 손대지 않는다. `tests/saju.test.ts`의 2027-02-04 단언은 `hour 12 → 정미`, `hour 5 → 병오` 두 줄로.
- **시간 모름 + 절입일**: 정오로 계산해 표를 보여 주되 `basis.boundaryWarning = { kind: 'jeolip', at: 'HH:MM', alt: '○○월주(또는 년주)' }`를 채우고 표 아래에 "이날 HH:MM에 절기가 바뀌어요. 태어난 시간에 따라 월주가 ○○일 수도 있어요" 한 줄. 23시~1시 칸을 고른 경우는 `kind: 'midnight'` 안내("밤 11~12시는 그 날짜로 봤어요"). 골든 테스트에 2027-02-04 시간 모름 케이스 추가.
- **대운 나이**: 라이브러리 `startAge`(출생~절입 일수÷3, 반올림)는 **만 나이**로 본다. 표기 "만 7세부터(세는 나이 8세)". `isCurrent`는 `asOfYear − 출생연도`(만 나이 근사)가 `[startAge, startAge+10)`에 드는 구간. 입력 `asOfYear`는 서버가 KST 올해로 채운다(결정성: 테스트는 명시 값).
- **/fortune 폼·풀이**: (a) 시간 select를 13칸으로 교체, 성별은 **묻지 않음**(대운을 /fortune에서는 안 보여 줌) → 엔진 입력 `gender`는 선택이고 없으면 `daeun`은 빈 배열. (b) `fortuneService`가 풀이 글 선택에 쓰는 `강한오행·약한오행`은 **새 엔진의 8글자(시간 모름이면 6글자) 집계**로 바꾼다. 표의 막대와 아래 글이 같은 계산을 써야 신뢰 장치가 성립한다. 영향받는 `tests/fortune*` 기대값은 같은 커밋에서 갱신.
