# 화면 개편 설계: 색·메뉴·캐릭터·움직임 (2026-11-13)

시안: https://claude.ai/artifact/3ZAHMjwtZHe1Kgss1HZ66F (v4, 사용자가 "좋아, 이대로"라고 승인)
논의 기록: `docs/design/2026-11-13-정리.md`, 조사: `docs/design/2026-11-13-character-popularity-research.md`

## 1. 왜 하는가

- 지금 화면(베이지 종이 + 바탕체)은 "운세집" 인상이 강하고, 사용자가 "너무 별로"라고 했다.
- 20~30대가 카카오톡 공유와 검색으로 들어와 폰으로 본다. 요즘 앱처럼 보이고, 결과를 공유하고 싶게 만드는 것이 목적이다.
- 사용자의 최종 목적은 유입 늘리기다. 다만 조사 결과 디자인·캐릭터는 검색 유입을 늘리지 못하고 **들어온 사람의 체류와 공유**를 늘린다. 이 설계의 성공 기준도 그쪽에 둔다.

## 2. 목표 / 하지 않는 것 / 실패로 보는 것

**목표**
- 색과 글꼴을 시안 B(블루·라임, 고딕)로 바꾼다.
- 메뉴를 "홈 / 전체 / 오늘" 3탭으로 줄이고, 홈에서 같은 테스트가 여러 번 나오는 것을 없앤다.
- 캐릭터 여섯(해태·저승사자·구미호·무당·백호·도깨비)을 테스트 묶음의 얼굴로 쓴다.
- 화면 진입, 로딩, 결과 공개, 메뉴 이동에 움직임을 넣는다.

- 영어판을 만들어 해외 방문자가 들어오고 쓸 수 있게 한다(5.5절).
- 페이지가 빨리 뜨게 하고, 기다리는 동안 보이는 화면을 다듬는다(5.7절).

**하지 않는 것(이번 범위 밖)**
- 손금, 가상 아이돌 실사, "나는 어떤 캐릭터?" 새 테스트.
- 긴 글(띠별 운세, MBTI 유형, 삼국지 열전, 밈 능력고사)의 영어판.
- 부적·삼국지 일기토·삼국지 초상화의 전용 색과 그림(그대로 둔다).
- 문구·계산 로직 변경.

**실패로 보는 것**
- 검색 유입이 줄어든다(주소·제목·본문·구조화 데이터가 바뀌어서).
- 결과 저장 이미지나 카카오톡 미리보기가 깨지거나 중간 프레임이 찍힌다.
- 첫 화면이 스크립트가 돌기 전까지 비어 보인다.
- 캐릭터가 특정 영화·드라마·마스코트를 닮았다는 말을 듣는다.
- 핑크가 주색으로 보인다.

## 3. 지켜야 할 것(코드에서 확인한 사실)

- 색은 `src/app/globals.css`의 `@theme` 토큰 이름(paper, card, card-2, line, ink, muted, accent)으로 쓰인다. 사용처는 `text-muted` 354곳, `border-line` 200곳, `bg-card` 138곳 등이다. **토큰 값만 바꾸면 화면 전체가 따라온다.**
- `tests/design.test.tsx`가 토큰의 hex 값, 글꼴 파일 이름(GowunBatang·NotoSansKR·Silkscreen), OFL 파일, 대비 4.5 이상, `font-black` 금지, 옛 민화 색 금지를 고정한다. 값을 바꾸면 이 테스트를 같이 고친다.
- `font-serif`가 83개 파일 170곳에 쓰인다. `@theme inline`의 `--font-serif`가 가리키는 글꼴만 바꾸면 한 번에 바뀐다.
- 글꼴은 자체 호스팅만 쓴다(`next/font/local`, Google Fonts 금지). 한글은 `scripts/font-subset.mjs`로 2,350자만 남긴다.
- 메뉴 데이터는 `src/content/navigation.ts` 한 곳이다(TABS, CATEGORIES, tabForPath, NEXT_BY_TEST). 하단 탭 5칸은 `e2e/tabbar.spec.ts`, 홈 구성은 `tests/home.test.ts`·`e2e/home.spec.ts`, 허브는 `tests/hubs.test.ts`·`e2e/hubs.spec.ts`가 고정한다.
- 결과 카드는 `modern-screenshot`으로 캡처하고 `no-screenshot` 요소를 뺀다. 미리보기 이미지는 `/api/og`·`/api/og/result`가 따로 그린다(자체 색·글꼴).
- 이모지는 제목·버튼·메뉴에 쓰지 않는다. 가짜 참여자 수를 쓰지 않는다. `prefers-reduced-motion`을 지킨다.
- 허브 주소(`/face-tests`, `/unse`, `/mbti`)와 모든 테스트 주소는 유지한다(검색 색인).
- 11/12 판정(12/15까지 새 기능 중단)은 사용자가 11/13에 바꿨다: **지금 바로 시작한다.** 대신 검색 유입이 줄지 않게 SEO를 설계의 조건으로 둔다(5.6절).

## 4. 접근 방법

| 방법 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 한 번에 | 색·메뉴·캐릭터·움직임을 한 브랜치에서 다 바꿔 한 번에 배포 | 중간 상태가 없음 | 변경이 커서 테스트 수십 개가 한꺼번에 깨지고, 문제가 생기면 원인을 가리기 어려움 |
| **B. 단계별(선택)** | 토큰 → 메뉴 → 캐릭터 → 움직임 순으로 따로 배포 | 단계마다 작고 되돌리기 쉬움. 1단계만으로도 인상이 바뀜 | 며칠간 새 색에 옛 구성이 섞여 보임 |
| C. 새 화면만 | 홈과 결과 카드만 새로 만들고 나머지는 옛 모습 | 가장 빠름 | 페이지마다 다른 사이트처럼 보임 |

B를 고른 이유: 색과 글꼴이 토큰으로 묶여 있어 1단계가 작고(값 몇 개와 테스트), 그것만으로 "운세집" 인상이 사라진다. 뒤 단계는 앞 단계 결과를 보고 줄이거나 멈출 수 있다.

## 5. 단계별 설계

### 1단계: 색과 글꼴 (토큰 교체)

- 토큰 값(시안 B):
  - paper `#F7F8FC`, card `#FFFFFF`, card-2 `#EEF1FA`, line `#E1E6F5`
  - ink `#1A1B25`, muted `#5E6070`, accent `#2D55FF`
  - 새 토큰 `lime` `#C6F24E`(칩·스티커 전용, 글자는 ink만 올린다)
- 주 버튼은 `bg-ink`에서 `bg-accent text-white`로 바꾼다(시안 기준). 사용처 83곳이라 공통 클래스가 있는지 계획 단계에서 확인한다.
- 흰 카드가 연한 배경과 구분되도록 카드에 `border-line` 1px을 둔다.
- 글꼴: 제목·본문 모두 Pretendard(OFL). `--font-serif`와 `--font-sans`를 둘 다 Pretendard로 가리키게 하고, `font-serif` 클래스 170곳은 이번에 지우지 않는다(뒤에 정리). 굵기는 400·600·700·800, 900은 계속 금지.
- Gowun Batang·Noto Sans KR 파일과 테스트는 Pretendard로 바꾼다. Silkscreen(삼국지 카드)과 부적 글꼴은 그대로.
- `blush`(얼굴 그림 볼 홍조)는 `SmileFace`가 남는 동안 유지한다.
- OG 이미지 두 경로의 색·글꼴을 같은 값으로 맞춘다.
- 부적·일기토·삼국지 카드 전용 토큰은 손대지 않는다. 다만 먹빛 부적 화면처럼 공용 푸터·탭바가 따라가는 곳은 눈으로 확인한다.

### 2단계: 메뉴와 홈

- 하단 탭 3칸: 홈(`/`), 전체(`/all`, 새 주소), 오늘(`/today`, 새 주소). 표시 막대가 미끄러진다.
- `navigation.ts`의 각 항목에 `tags`(face·fortune·match·play)와 `daily` 표시를 더한다. 홈 칩, 전체, 오늘, 푸터가 모두 이 데이터에서 나온다. `PlayTogether`의 따로 적힌 목록은 없앤다.
- 홈: 로고와 검색 → 칩(전체·얼굴·운세·궁합·게임) → 대표 카드 1장(관상, 시즌에는 시즌 카드) → 2열 카드 → "오늘 새로 바뀐 것" 가로 줄 → 쿠팡·시즌 추천·FAQ(기존 그대로 아래에).
  - 칩은 이동이 아니라 같은 화면에서 카드를 거른다. 서버 HTML에는 모든 카드가 있고(색인 유지), 거르기는 클라이언트에서 한다.
- 전체: 검색창(제목·설명 글자 거르기)과 모든 테스트 목록.
- 오늘: 오늘의 운세, 오늘의 MBTI 운세, 밈 능력고사, 시즌 부적.
- 허브 3곳은 주소와 본문을 유지하고, 목록 모양만 새 카드로 맞춘다. `tabForPath`는 허브와 테스트 페이지에서 "전체"를 돌려준다.
- 테스트 시작 화면과 결과 화면 아래에 "다른 테스트 둘러보기" 줄을 둔다(같은 컴포넌트). 결과 화면에서는 기존 `NextSteps`·`NextTests`와 합쳐 하나로 보이게 한다. 캡처에서 빠지도록 `no-screenshot`.
- 헤더의 눌리지 않는 달 장식은 없앤다.

### 3단계: 캐릭터

- 여섯과 맡는 자리: 해태(관상·홈 대표·로딩), 저승사자(사주·운세), 구미호(궁합), 무당(부적), 백호(동물상·삼국지), 도깨비(밈 능력고사·게임).
- 그림은 제미나이로 뽑은 ③ 화풍(극장판 애니메이션 화면 느낌), 멤버 색 단색 배경의 정사각 그림. 지시문은 `docs/design/2026-11-13-character-style-prompts.md`와 시안 v4 때 쓴 것.
- 실제 적용 전에 원본을 다시 받는다: 지금 가진 것은 화면 캡처(454px)다. 제미나이 대화 "Korean Folklore 3D Character Lineup"에서 원본을 내려받고, 저승사자·무당은 상반신으로 다시 뽑는다.
- 파일: `public/images/cast/<이름>.webp`(512px)와 얼굴 위주로 자른 작은 판(160px). `next/image`로 쓴다.
- 쓰는 곳: 홈 대표 카드, 2열 카드와 목록의 썸네일(`CategoryItem.thumb.image`), 로딩 화면, 결과 카드.
- 결과 카드: 요소는 넷(결과 이름, 점수, 캐릭터 하나, 워터마크)과 특징 칩 둘까지. **사용자 얼굴 사진은 카드에 넣지 않는다.** 삼국지 결과는 장수 초상화가 주인공이므로 캐릭터를 넣지 않는다.
- OG 미리보기(1200×630)는 왼쪽 글, 오른쪽 캐릭터로 나눈다.
- 닮은꼴 점검: 적용 전에 여섯 장을 한 번씩 눈으로 확인한다(파란 호랑이·까치 한 쌍, 갓 쓴 남자 여러 명 구도 금지). 그림 속 제미나이 AI 표시는 지우지 않는다.
- 개인정보처리방침이나 소개 페이지에 "캐릭터 그림은 AI로 만들었다"는 한 줄을 둔다.

### 4단계: 움직임

- 화면 진입: 카드가 차례로 올라온다. 처음 6개까지만, 서버 HTML에서는 보이는 상태로 시작한다(투명에서 시작하지 않는다).
- 누름: 0.96배로 눌렸다 돌아온다.
- 메뉴 이동: 탭 표시 막대가 미끄러지고, 탭 아이콘이 한 번 튄다. 페이지 전환 효과는 Next의 화면 전환 기능을 쓸 수 있는지 계획 단계에서 확인하고, 안 되면 막대만 한다.
- 로딩: 사진 테스트의 분석 중 화면에 살펴보는 줄과 캐릭터, 단계 문구. 관상의 기존 `RevealMotion`(건너뛰기 포함)은 유지하고 모양만 맞춘다.
- 결과 공개: 동그랗게 열림 → 캐릭터 등장 → 칩 → 점수 올라가기(0.8초) → 도장. 전부 한 번 재생하고 멈춘다.
- 캡처는 움직임이 끝난 상태에서만 한다. 미리 만들어 두는 공유 이미지(`useScreenshot(result)`)는 움직임을 끈 상태(`data-capture`)로 찍는다.
- `prefers-reduced-motion`이면 전부 건너뛰고 완성 상태를 바로 보인다.

### 5.5 언어 (한국어·영어)

**원칙: 언어마다 주소를 따로 두고, 검색 로봇에게는 절대 자동 전환을 하지 않는다.**

- 주소: 한국어는 지금 주소 그대로(`/face2`). 영어는 앞에 `/en`(`/en/face2`). 한국어 주소가 하나도 안 바뀌므로 지금 색인은 그대로 남는다.
- 각 페이지에 `hreflang`(ko, en, x-default=한국어)을 서로 걸고, 사이트맵에도 영어 주소와 언어 짝을 넣는다. `<html lang>`은 페이지 언어에 맞춘다(지금은 `ko` 고정이라 루트 레이아웃을 언어별로 나눠야 한다).
- 화면마다 언어 바꾸기: 헤더 오른쪽에 지구 아이콘 + "한국어 / English". 누르면 **같은 페이지의 다른 언어판**으로 간다. 영어판이 없는 페이지에서는 영어 홈으로 가고 "이 페이지는 한국어만 있어요" 안내를 한 줄 띄운다.
- 자동 감지: 처음 온 사람의 접속 국가(Vercel `x-vercel-ip-country`)와 브라우저 언어를 본다.
  - 한국이 아니고 브라우저 언어도 한국어가 아니면, 페이지는 그대로 두고 위쪽에 "View this page in English" 띠를 띄운다(닫기 가능).
  - 사용자가 언어를 한 번 고르면 쿠키에 기억하고, 다음부터는 그 언어로 바로 보낸다(쿠키는 사람만 가지므로 검색 로봇에는 영향이 없다).
  - **IP만 보고 바로 다른 언어로 보내지 않는다.** 구글 로봇은 주로 미국 IP로 오기 때문에, 그렇게 하면 한국어 페이지가 검색에서 사라진다. 구글도 자동 전환 대신 이런 안내 띠를 권한다.
- 언어 방식 확정(2026-11-13): 위 안내 띠 + 선택 기억 방식. IP만 보고 바로 넘기지 않는다.
- **언어는 처음부터 여러 개를 받을 수 있게 만든다.** 언어 목록을 한 곳(`src/lib/i18n/locales.ts`)에 두고, 언어 하나를 더하는 일이 "목록에 한 줄 + `src/content/<언어>/` 문구 파일"로 끝나게 한다. 주소 앞자리(`/en`, `/ja`, `/zh-tw`), hreflang, 사이트맵, 언어 메뉴가 이 목록에서 자동으로 나온다.
- 이번에 번역하는 것은 영어 하나다. 일본어·중국어 등은 데이터를 보고 하나씩 더한다(사용자 뜻). 더하는 기준:
  - 영어판을 연 뒤 GA에서 그 나라(또는 그 브라우저 언어) 방문이 4주 연속 주 20세션 이상, 또는
  - 서치 콘솔에서 그 나라 노출이 영어판 페이지 기준 주 200회 이상.
  - 후보 순서(조사 전 가설): 일본어(일본은 "진단" 테스트 문화가 크고 한국 관심도 높음) → 번체 중국어(대만·홍콩은 구글을 씀). 중국 본토는 구글이 막혀 있어 검색으로 들어오기 어려우므로 간체 중국어는 마지막.
- 1차 영어판 범위: 홈, 전체, 관상(`/face2`), 동물상(`/animal`), 얼굴 궁합(`/face-match`), 각 결과 공유 착지, 캐릭터 소개. 사진 테스트는 계산이 같아 문구만 옮기면 된다. 사주·운세·삼국지는 2차.
- 문구는 `src/content/en/`에 파일로 둔다(한국어 파일과 같은 키). 기계 번역 그대로 쓰지 않고 한 번 다듬는다. 캐릭터 이름은 소리대로(Haetae, Jeoseung Saja, Gumiho, Mudang, Baekho, Dokkaebi) 쓰고 첫 등장에 한 줄 설명을 붙인다.
- 영어판 결과 카드·미리보기 이미지·카카오톡 대신 기본 공유창. GA에는 `lang` 값을 붙여 언어별로 본다.

### 5.6 검색(SEO)에서 지킬 것

- 주소는 하나도 바꾸지 않는다. 새로 생기는 주소는 `/all`, `/today`, `/en/...`뿐이다.
- 페이지 제목·설명·`h1`·`PageGuide` 본문·FAQ·구조화 데이터는 그대로 둔다(겉모습만 바꾼다). 11/25 제목 실험 대상 글은 건드리지 않는다.
- 홈 칩과 전체의 거르기는 클라이언트에서만 한다. 서버 HTML에는 모든 카드와 링크가 있어야 한다.
- `/all`, `/today`는 각자 제목·설명·canonical을 갖고 사이트맵에 넣는다. 허브 3곳(`/face-tests` 등)은 소개 글이 있는 원본으로 남긴다.
- 캐릭터 그림에는 `alt`(예: "해태 캐릭터")와 크기를 넣어 이미지 검색에도 잡히게 한다.
- 영어판은 5.5절대로 `hreflang`으로 묶어 중복 문서로 보이지 않게 한다.
- 배포 단계마다 IndexNow를 보내고, 영어 주소는 서치 콘솔에 색인 요청한다.
- 속도도 검색 순위에 들어가므로 5.7절을 같이 한다.

### 5.7 로딩(빨리 뜨기와 기다리는 화면)

**지금 상태(코드에서 확인)**: 삼국지 초상화 115장이 장당 최대 약 400KB JPG이고, 화면의 그림 34곳이 `next/image` 없이 `<img>`로 들어가 있다. 페이지별 `loading.tsx`가 하나도 없다. 사진 테스트는 얼굴 인식 모델(약 4MB)을 받아야 분석이 시작된다.

- 그림: 캐릭터와 초상화를 webp로 바꾸고 `next/image`로 크기·지연 로딩을 맞춘다. 첫 화면 그림 하나만 먼저 받는다(`priority`).
- 글꼴: Pretendard를 필요한 글자만 남겨 자체 호스팅하고 미리 받는다. 바뀌는 순간 화면이 출렁이지 않게 한다.
- 페이지 이동: ~~주요 경로에 `loading.tsx`(뼈대 화면)를 둔다~~ → 하지 않는다(2026-11-13 검토). 루트에 두면 404·리다이렉트 상태 코드가 200으로 바뀌고, 정적 페이지에 두면 서버 HTML 본문이 숨김 상태로 나가 네이버 봇이 못 읽을 수 있다. 정적 페이지는 링크 미리 받기로 이미 바로 열린다.
- 사진 테스트: 시작 화면이 뜨면 바로 모델을 미리 받기 시작하고, 사진을 고르기 전까지 끝나게 한다. 덜 받았으면 분석 화면에 "준비 중" 단계를 하나 더 보인다.
- 분석 중 화면: 5절 4단계의 로딩(살펴보는 줄, 캐릭터, 단계 문구). 실제 진행과 맞지 않는 가짜 진행률은 쓰지 않는다(단계 문구만 바꾼다).
- 움직임은 CSS만 쓴다. 움직임 라이브러리는 넣지 않는다(카카오톡 인앱의 중저가 폰 기준).
- 확인: 단계마다 모바일 Lighthouse의 LCP·CLS를 재서 지금보다 나빠지지 않게 한다.
