# unse-ai.com 살리기 — 개선 설계

작성일: 2026-10-26

## 왜 하나

- 목표는 **수익**이다. 수익원은 애드센스(방문자 수)가 메인이고, 쿠팡 파트너스는 보조다.
- 근거는 실제 데이터다.
  - 사이트는 런칭(2026-01) 후 방치됐는데도 검색 유입이 조금씩 늘고 있다.
  - 구글 클릭은 10개월간 72회, 최근 3개월 32회다. CTR은 10~15%로 높다.
  - 최근 7일 Vercel 방문자는 15명이다. 구글 6, 네이버 4, 모바일 80%다.
  - 주력 검색어는 "ai 관상 테스트 무료", "무료관상" 등이다.
- 쿠팡 수익은 1년 동안 8,042원(1~2월)이다. 일반 상품 캐러셀은 사실상 효과가 없다.
- 12~1월은 신년운세 검색 시즌이다. 11월 안에 배포해야 시즌에 순위가 잡힌다.

## 핵심 문제

1. **색인이 안 된다.** 사이트맵의 7개 URL 중 구글 색인은 2개(메인, 오늘의 운세)뿐이다.
   - 모든 테스트 페이지가 `"use client"`라서 서버 HTML에 본문 텍스트가 거의 없다. 업로드 버튼과 짧은 안내 문구 정도만 있다.
   - 리디렉션 3건은 http/www 변형이라 문제가 아니다.
2. **Gemini 의존**이 남아 있다. `/face`(AI 관상, 하루 1회)와 `/samguk`이 `/api/analyze`, `/api/samguk`에서 Gemini를 호출한다. 방문자가 늘면 비용이 생긴다.
3. **연도가 낡았다.** 메인과 신년운세가 "2026" 기준이다. 2027(정미년) 콘텐츠가 없다.
4. 쿠팡 위젯이 결과와 무관한 일반 캐러셀이다.
5. **애드센스 계정이 비활성 상태다.** 2026-10-26에 확인했고, 사유는 활동 없음이다.
   - 코드에는 애드센스 스크립트(`layout.tsx`)와 `ads.txt`만 있고 광고 단위는 없다. 지금까지 광고 수익은 0이었다.
   - 다시 쓰려면 사용자가 전화번호 인증을 하고 사이트 재심사를 받아야 한다.
   - 그래서 1단계는 "재심사 통과 가능한 사이트"도 겸한다. 본문 분량을 늘리고, about·privacy 페이지를 유지하고, 중복 페이지(`/face`)를 정리한다.

## 목표 / 비목표 / 반목표

**목표**
- 테스트 페이지 전부 구글·네이버에 색인
- 2027 신년운세 시즌 유입 확보
- AI 호출 비용 0원. 결과는 규칙(사주 계산, 얼굴 랜드마크)과 미리 작성한 해석 데이터로 만든다.
- 결과 화면에서 공유(캡처)가 쉽고, 캡처 이미지에 사이트 주소가 남는다.

**비목표**
- 로그인, 회원, 유료 결제
- 새 도메인이나 새 사이트
- 사용자 대상 실시간 AI 기능

**반목표** (기술적으로 돌아가도 실패로 본다)
- 날짜별·조합별로 내용만 살짝 바꾼 얇은 페이지 대량 생성. 구글 "scaled content abuse" 페널티 위험이 있다.
- 결과 직전 광고, 결과 버튼처럼 보이는 광고 배치
- 사용자 사진의 서버 전송

## 단계

### 1단계: 검색 기반 다지기 (최우선)
- 테스트 페이지(`/face2`, `/animal`, `/samguk`, `/fortune`, `/fortune/daily`)를 **서버 컴포넌트 껍데기 + 클라이언트 테스트 위젯**으로 분리한다.
  - 서버 HTML에 소개, 보는 법, 결과 유형 미리보기, FAQ 텍스트가 들어가게 한다. 페이지당 의미 있는 본문을 둔다.
- 페이지 간 내부 링크(다른 테스트 추천)를 추가한다.
- 사이트맵은 `src/app/sitemap.ts`가 동적으로 생성한다(CLAUDE.md의 `public/sitemap.xml` 설명은 틀렸으니 고친다). `lastModified: new Date()`를 페이지별 실제 변경일로 바꾼다.
- 삼국지 페이지 footer에 남은 "© 2024 Samguk Persona"를 정리한다.
- 주력 키워드("AI 관상 테스트 무료")를 `/face2`의 title과 H1로 옮긴다. `/face` 통합(2단계)과 짝을 이룬다.
- 배포 후 사용자가 직접 할 일
  - 애드센스 계정 재활성화: Claude가 Aside 브라우저로 진행한다. 사용자는 전화번호 인증 코드 입력과 약관 동의만 직접 하거나 그 자리에서 승인한다. 신청 시점은 1단계 배포 후다(본문이 늘어난 상태로 심사받기 위해).
  - Vercel 대시보드 도메인 설정에서 www 리디렉션 307 → 308. 레포에는 리디렉션 설정이 없다.
  - 구글 서치 콘솔 사이트맵 재제출, 주요 URL 색인 요청
  - 네이버 서치어드바이저 사이트맵 제출
- 애드센스 승인 후 광고 단위를 배치한다. 결과 영역과 공유 버튼 아래, 본문 텍스트 사이에만 둔다(반목표 참고).

### 2단계: Gemini 제거
- `/face`를 `/face2`로 308 리디렉션해 하나로 합친다. `/face2`는 이미 브라우저 안에서만 분석하는 무제한 무료 버전이다.
  - 함께 정리할 것: sitemap에서 `/face` 제거, 메인 등 내부 링크, `/face/layout.tsx`, 루트 layout FAQ JSON-LD의 관련 문구
- `/samguk`을 Gemini 없는 **닮은꼴 매칭 로직**으로 바꾼다. 사용자 결정이고, Claude가 깊게 설계·구현한다.
  - **바꾸는 이유:** 지금은 Gemini에 사진과 54명 목록을 주고 고르게 한다.
    - 실제 얼굴 측정이 없다.
    - 유명 인물 쪽으로 쏠린다(사용자도 "이상한 장수로 몰린다"고 체감).
    - 같은 사진도 결과가 바뀐다.
    - 목록 밖 이름이 나오면 무조건 조조로 처리한다.
    - 성별도 Gemini로 추측한다.
  - **얼굴 측정 엔진: MediaPipe Face Landmarker** (478점, 브라우저 실행, 무료). 사용자 결정이다.
    - 사진은 여전히 서버로 보내지 않는다.
    - 모델 파일은 `public/models/`에 둔다.
  - **특징:** 3단계 버킷('small/medium/large')이 아니라 연속 비율 15~20개를 쓴다. 눈 가로/세로, 눈꼬리 각도, 눈 사이 거리, 코 길이·폭, 입 너비, 입꼬리, 턱 각도, 얼굴 가로세로비, 광대 폭 등이다.
    - 얼굴 크기와 기울기에 대해 정규화한다.
    - 랜드마크로 실제 측정 가능한 것만 쓴다(귀, 눈썹 굵기 같은 추정값 금지).
  - **장수 프로필:** 54명 전원에게 같은 축의 수치 프로필과 특징별 가중치(그 인물의 대표 특징)를 붙인다. 인물별 서사(CLAUDE.md의 시그니처 디테일)와 맞아야 한다.
  - **매칭:** 가중 거리로 가장 가까운 장수를 고른다. 결정적이어야 한다(같은 사진이면 같은 결과).
  - **성별:** AI 추측 대신 사용자가 직접 선택한다.
  - **근거 표시:** 결과에 "왜 이 장수인지"를 보여준다. 예: 눈꼬리가 올라가고 턱선이 각져서 관우와 87% 일치.
  - **테스트 + 시뮬레이션 보정** (사용자 요청)
    - 테스트 프레임워크(vitest)를 도입한다. 지금 레포에는 테스트가 없다.
    - 단위 테스트: 특징 계산(정규화, 회전·크기 불변성), 매칭 결정성, 장수 프로필 데이터 무결성(54명 모두 프로필 보유, 값 범위)
    - **분포 시뮬레이션:** 실제 얼굴 비율 분포를 근사한 합성 특징 벡터를 대량(예: 1만 개) 생성해 매칭을 돌린다. 장수별 선택 비율을 측정한다.
      - 보정 목표(Claude의 판단): 모든 장수가 나온다. 어떤 장수도 성별 내 균등 비율의 3배를 넘지 않는다.
      - 목표를 넘으면 프로필과 가중치를 조정한다. 이 시뮬레이션을 테스트로 고정해 회귀를 막는다.
    - **실사진 회귀 세트:** 라이선스 문제없는 얼굴 이미지 소수(예: AI 생성 인물 사진)로 랜드마크 추출부터 결과까지 끝까지 확인한다. 기대 결과를 스냅샷으로 고정한다.
- **관상(`/face2`)과 동물상(`/animal`)도 MediaPipe로 옮긴다** (사용자 요청). 순서는 삼국지 먼저, 검증 후 이전이다.
  - 같은 측정 모듈을 공유하고, face-api와 그 모델 파일은 제거한다.
  - 동물상도 같은 분포 시뮬레이션으로 8종 쏠림을 점검한다.
- 그 뒤 `/api/analyze`, `/api/samguk`과 `@google/generative-ai` 의존성, `GEMINI` 환경변수를 삭제한다.

### 3단계: 2027 시즌 콘텐츠 (11월 중 배포)
- `/fortune`의 연도 로직과 문구를 2027 정미년으로 갱신한다. 메인 문구도 함께 바꾼다.
- **2027 띠별 운세 12페이지**(`/fortune/2027/[띠]`)를 정적 생성한다.
  - 해석 텍스트는 Claude가 작성해 레포의 데이터 파일로 커밋한다. 띠마다 실질적으로 다른 내용이어야 한다.
  - 구성(Claude의 판단): 총운, 재물, 연애·관계, 직장·학업, 건강, 분기별 흐름(4개), 행운 요소, 조언. 띠당 약 1,500~2,000자. 월별 12개 쪼개기는 하지 않는다(얇은 콘텐츠 위험).
  - 출생연도로 내 띠를 찾는 표를 넣는다.
  - 각 페이지에서 "내 사주로 자세히 보기"(`/fortune`)로 연결한다.
  - 사용자는 원하면 게시 전에 검수한다. 기본값은 Claude 작성 후 바로 게시다.
- 띠 기준은 **입춘(2월 4일경)**으로 바로잡는다(Claude의 판단). 지금 `saju.ts`는 양력 연도만 써서 1~2월생 판정이 틀릴 수 있다. 사주명리 표준이 입춘이고, 신뢰가 핵심이라 고친다. `/fortune/daily`의 "음력 설 전 출생" 체크도 같은 기준으로 맞춘다.

### 4단계: MBTI 섹션 (사용자 요청)
- 근거: 자동완성에서 "mbti 궁합", "mbti 궁합표", "mbti 궁합 isfj"(유형별), "mbti 운세", "mbti 오늘의 운세"가 확인된다.
- **16유형 페이지** (`/mbti/[유형]`). 각 페이지에 담는 것:
  - 유형 요약
  - 16유형 전체와의 궁합: 연애, 친구, 직장 관계별 점수와 설명
  - 나랑 맞는 여행지 (국내·해외 각 몇 곳, 이유 포함)
  - 어울리는 직업과 일하는 방식
  - 이달의 MBTI 운세 (월 1회 갱신, 6단계 파이프라인)
- **궁합 계산기 1페이지** (`/mbti/궁합`): 두 유형을 고르면 결과 카드를 보여준다. 커플·친구 공유용이다.
  - 조합별 136개 개별 페이지는 만들지 않는다(얇은 콘텐츠 반목표). 조합 데이터는 계산기와 유형 페이지 안에서 쓴다.
- 모든 데이터는 Claude가 작성해 레포 데이터 파일로 둔다. 실시간 AI 호출은 없다.
- 기존 사이트와 연결한다. 메인 "마당놀이" 섹션에 노출하고, 띠별·사주 결과에서 "MBTI 궁합도 보기"로 내부 링크를 건다.
- MBTI × 띠 결합 운세처럼 경쟁 사이트에 없는 조합은 후속 후보로 둔다(이번 범위 아님).

### 5단계: 결과 공유 + 맥락형 쿠팡
- 결과 카드 하단에 `unse-ai.com`과 테스트 이름을 넣는다. 캡처만 돌아도 유입 경로가 남게 한다.
- 공유 버튼은 광고보다 위에 둔다.
- 메인의 일반 쿠팡 캐러셀을 빼고, 시즌·결과 맥락형 추천으로 바꾼다.
  - 11월: 수능 합격 선물
  - 12~1월: 신년·설 선물
- 쿠팡 링크는 쿠팡 파트너스에서 생성한다. 코드에는 데이터 파일 기반 추천 슬롯만 만들어 두고, 링크는 나중에 채운다. 링크가 비어 있으면 슬롯을 숨긴다.

### 6단계 (선택, 앞 단계 성과를 본 뒤): 주기 데이터 갱신
- 대상: MBTI 이달의 운세, 띠별 오늘(또는 이번 주) 운세, 달력 이벤트 특집
- 띠별 오늘의 운세 같은 갱신형 데이터를 Claude가 주기적으로(예: 주 1회 예약 작업) 생성해 레포에 커밋한다. Vercel이 자동 배포한다.
- 페이지는 고정 URL을 유지하고 내용만 갱신한다. 날짜별 새 페이지는 만들지 않는다.
- DB(Supabase 등)는 레포 파일로 감당이 안 될 때만 도입한다.
- 달력 이벤트(수능, 크리스마스, 설, 밸런타인) 특집은 이 파이프라인으로 미리 만든다.
