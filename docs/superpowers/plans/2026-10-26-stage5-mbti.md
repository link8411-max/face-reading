# 5단계: MBTI 섹션 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** MBTI 16유형 페이지(유형 요약, 16유형과의 궁합, 여행지, 직업, 이달의 운세)와 궁합 계산기 1개, MBTI 허브를 만들어 하단 MBTI 탭을 실제 페이지로 바꾼다.

**Architecture:**
- 궁합은 네 축(E/I, S/N, T/F, J/P)의 같고 다름을 맥락별(연애·친구·직장) 가중치로 점수화하는 규칙 함수다. 결정적이고 대칭이다.
- 설명 문장은 축별 관계 문장을 조합한다.
- 유형별 본문(요약, 여행지, 직업, 이달의 운세)은 Claude가 작성해 데이터 파일로 둔다.
- 페이지는 정적 생성한다. 계산기만 클라이언트 컴포넌트다.

**Tech Stack:** Next.js 16, TypeScript, vitest, Playwright

**Spec:** `docs/superpowers/specs/2026-10-26-unse-ai-revival-design.md` (5단계 MBTI)

## Global Constraints

- 주소
  - 허브 `/mbti`: 지금의 준비 중 페이지를 대체한다. 색인을 허용하고 사이트맵에 넣는다.
  - 유형 페이지 `/mbti/[type]`: 소문자 슬러그 16개(`intj` … `esfp`)
  - 계산기 `/mbti/match`
- 조합별(136개) 개별 페이지는 만들지 않는다(얇은 콘텐츠 반목표). 조합 결과는 계산기와 유형 페이지 안의 표에서만 보여준다.
- 궁합 점수
  - 정수 55~98, 대칭(a↔b 동일), 결정적이다.
  - 같은 유형끼리는 최고점이 아니다. 너무 같으면 시너지가 적다는 통설을 반영한다.
  - "재미로 보는 궁합"임을 페이지에 밝힌다.
- 유형 페이지 본문(유형 고유 글 + 궁합 섹션 문장)은 공백 포함 1,500자 이상이다.
- 이달의 운세: 현재 달(2026년 11월) 기준으로 작성한다. 데이터에 `month: '2026-11'`을 두고, 화면에는 "2026년 11월"로 표시한다. 월 1회 갱신은 7단계 파이프라인 범위다.
  - 지난달 데이터가 그대로 노출되지 않게, 현재 달과 다르면 해당 섹션을 숨기는 테스트를 둔다.
- 메뉴: `navigation.ts`의 mbti 묶음에 항목(궁합 계산기, 16유형 보기)을 넣는다. 하단 탭은 그대로 둔다.
- 결과 이미지 저장은 기존 `useScreenshot`을 쓴다. 캡처 영역에 사이트 주소를 넣는다(4b 원칙을 계산기에 먼저 적용).
- 배포는 사용자 승인 후에만 한다.

## Review Focus

1. **유형 입력 실수**(소문자, 공백, 잘못된 문자): 계산기는 선택형(버튼)이라 자유 입력이 없다. 주소의 잘못된 유형(`/mbti/abcd`)은 404여야 한다(Task 3 E2E).
2. **궁합 점수 분포 쏠림**: 모든 쌍이 90점 이상이면 재미가 없다. 16×16 분포의 최소·최대·평균을 테스트로 고정한다(Task 1).
3. **이달의 운세 기간 만료**: 12월이 되면 11월 운세가 그대로 보이면 안 된다(Task 2 테스트, 섹션 숨김).
4. **계산기 공유 이미지**: 저장 이미지에 두 유형과 점수, 사이트 주소가 들어가야 한다(Task 3).
5. **허브 noindex 해제**: 기존 준비 중 페이지의 noindex가 남으면 MBTI 전체가 검색에 안 나온다(Task 3 테스트).

### Task 1: 궁합 계산 규칙
**Files:** Create `src/lib/mbti/compat.ts` · Test `tests/mbti/compat.test.ts`
**Interfaces:**

```ts
export const MBTI_TYPES = ['INTJ','INTP','ENTJ','ENTP','INFJ','INFP','ENFJ','ENFP','ISTJ','ISFJ','ESTJ','ESFJ','ISTP','ISFP','ESTP','ESFP'] as const
export type MbtiType = typeof MBTI_TYPES[number]
export type Context = 'love' | 'friend' | 'work'
export function isMbti(s: string): s is MbtiType
export function compatScore(a: MbtiType, b: MbtiType, ctx: Context): number          // 55~98
export function compatSummary(a: MbtiType, b: MbtiType): { love: number; friend: number; work: number; total: number; label: string; lines: string[] }
export function bestMatches(a: MbtiType, ctx: Context, n = 3): MbtiType[]
```

- 축별 기여도: 맥락마다 "같으면 좋은 축"과 "달라야 보완되는 축"의 가중치가 다르다.
  - 연애: S/N 같음 +, T/F 다름 +(보완), J/P 다름 약간 +
  - 친구: E/I 같음 +, S/N 같음 +
  - 직장: J/P 같음 +, T/F 다름 +, S/N 다름 약간 +
- 기본 70점에서 가감한 뒤 55~98로 자른다.
- `lines`: 축별 한 문장 4개(같음·다름에 따라 다른 문장, 긍정형). 외모 평가 문구 원칙과 같이 단점 지적형 표현은 쓰지 않는다.

- [ ] 테스트
  - 대칭성
  - 범위 55~98 정수
  - 결정성
  - 분포: 256쌍 total 평균 70~85, 최소 < 65, 최대 > 90
  - 같은 유형끼리는 그 유형의 최고점이 아니다
  - 유형마다 bestMatches 3개, 자기 자신은 제외
  - lines 4개에 "나쁜", "최악", "안 맞" 같은 표현이 없다
- [ ] RED → 구현 → GREEN → 커밋
