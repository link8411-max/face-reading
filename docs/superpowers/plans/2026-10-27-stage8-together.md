# 8단계: 함께 하는 테스트 실행 계획

> 실행: superpowers:executing-plans(네이티브). 단계는 체크박스로 추적한다.

**목표:** 얼굴 궁합(`/face-match`, 관계별·한 폰·초대 링크)과 우리 팀 삼국지(`/samguk/team`)를 만들고 결과 공유 링크·미리보기를 붙인다.

**구조:**
- 얼굴 한 장 분석을 공용 함수로 뽑는다(사진 → 동물상 또는 장수, 실패 이유 포함).
- 궁합·팀 규칙은 순수 함수로 두고 단위 테스트한다. 화면은 4b 공통 구성요소를 쓴다.

**설계:** `docs/superpowers/specs/2026-10-27-stage8-together-design.md`

## 공통 제약
- 링크에는 유형 키·관계만 담는다. 이름(별칭)·사진·얼굴 수치는 넣지 않는다. 허용 목록으로 검증하고, 잘못된 값이면 시작 화면으로 보낸다.
- 결과 공유 페이지는 검색 제외(noindex), canonical은 원래 기능 페이지, 사이트맵 제외.
- 사진은 브라우저 안에서만 분석한다. 실패(얼굴 없음·정면 아님·도구 로드 실패)는 그 칸에만 안내한다.
- 점수는 대칭·결정적이고 범위는 55~100이며, 관계마다 최고 쌍은 정확히 100점이다. 문구에 "최악·안 맞" 같은 부정어를 쓰지 않는다.
- GA: `test_name`에 `face_match`, `team_samguk`를 추가한다. `result_id`는 24자 필터를 지키며 `cat_dog_lover`, `liubei_4` 형식으로 보낸다.

## 리뷰 초점
1. 같은 두 동물상·관계면 한 폰이든 초대든 점수가 같다(작업 1 테스트).
2. 짝사랑에서는 초대 링크를 만들 수 없다(작업 3 E2E).
3. 팀 링크의 장수 id 2~6개는 허용 목록으로 검증하고 중복은 허용한다(작업 4 테스트).
4. 한 칸이 실패해도 다른 칸의 사진과 결과는 남는다(작업 3 E2E).
5. 별칭은 링크와 GA에 들어가지 않는다(작업 4 테스트·E2E).

### 작업 1: 얼굴 궁합 점수 규칙 (`src/lib/faceMatch/compat.ts`)
- `REL = ['friend','lover','crush']`
- `faceMatch(a, b, rel)` → `{ score, label, lines[2], others: {rel, score}[] }`
- 기준은 animalTypeDB의 best/worst다.
  - best 쌍은 높게, worst 쌍은 "서로 배우는 사이"로 준다.
  - 같은 동물상끼리는 친구 점수를 높게, 연인 점수는 중간으로 준다.
  - 관계마다 55~100으로 늘려 최고 쌍이 정확히 100점이 되게 한다.
- 테스트
  - 대칭·결정성
  - 범위와 관계별 최대 100점
  - 짝사랑은 "가능성" 문구
  - 부정어 없음
  - best 쌍이 worst 쌍보다 높음
  - 분포(평균 70~85)
- RED → 구현 → GREEN → 커밋

### 작업 2: 얼굴 분석 공용 함수 (`src/lib/face/analyzePhoto.ts`)
- `analyzePhoto(dataUrl, gender)` → `{ ok: true, z } | { ok: false, reason: 'tool'|'noface'|'frontal'|'read' }`
  - 이미지 압축 → 디코드 → MediaPipe → 정면 판정 → `toZ`
- `REASON_TEXT[reason]`: 한국어 안내
- 동물상·삼국지 페이지도 이 함수를 쓰도록 바꾼다(동작 동일). 기존 E2E로 확인한다.

### 작업 3: 얼굴 궁합 페이지·초대·공유
- `/face-match`
  - 관계 pill
  - 두 칸(별칭 없음, 칸 이름은 관계별), 칸마다 성별·사진, 칸별 오류
  - 결과 카드(ResultCard 확장: 두 동물상, 큰 점수, 다른 관계 작게)
  - ResultActions: 공유하기·저장·다시하기
- `?me=cat`: "나" 칸을 동물상으로 채운다(사진 없이). 관계를 고른 뒤 "그 사람 사진 올리기" 또는 "친구에게 초대 링크 보내기"(친구·연인만)를 쓴다.
- `/face-match/i/[key]?rel=friend|lover`
  - 초대 착지: "친구가 얼굴 궁합을 신청했어요(친구는 고양이상)"
  - 내 사진 한 장 → 결과 → 공유하기("결과 보내 주기")
- `/face-match/r/[a]-[b]?rel=` 결과 공유 착지, `/api/og/result?kind=face-match`
- `lib/shareLinks.ts` 확장
  - `faceMatchUrl`, `faceMatchInviteUrl`, `parseFaceMatch`, 1인칭 문구
  - 예: "나랑 그 사람 짝사랑 궁합 82%래. 너도 해볼래?", "우리 연인 궁합 87점이래. 너희도 해볼래?"
- 테스트
  - 단위: 링크 규칙, 메타(noindex·og)
  - E2E
    - 한 폰 흐름(개발용 얼굴 2장)
    - 짝사랑 초대 버튼 없음
    - 초대 링크 흐름
    - 한 칸 실패(빈 사진) 시 다른 칸 유지
    - 착지 메타

### 작업 4: 우리 팀 삼국지 (`src/lib/samguk/team.ts`, `/samguk/team`)
- `buildTeam(members: {character, nickname?}[])`
  - 역할: 군주(통솔+매력) → 책사(지력) → 선봉장(무력) → 살림꾼(정치), 이후 든든한 장수. 한 사람 한 역할, 동점이면 먼저 올린 사람.
  - 기운: 최다 세력, 기타면 군웅할거, 위·촉·오 동수 최다면 천하삼분, 그 밖 동수는 먼저 올린 사람의 세력
  - funStats 평균, 한줄평
- 페이지
  - 2칸에서 시작, "한 명 더"(최대 6)
  - 칸마다 별칭·성별·사진
  - 팀 결과는 남색 게임 카드 톤
- `/samguk/team/r/[ids]`(id 2~6, 하이픈 구분, 중복 허용, 별칭 없음), `/api/og/result?kind=team`
- 테스트
  - 단위: 역할·동수·기타·천하삼분·평균, 링크 검증, 별칭이 링크에 없음
  - E2E: 3명 흐름, 착지 메타
